이 격리 fixture에서 설치된 shape → spec → ticket → build 스킬을 순서대로 실제 Skill 도구로 호출하여 연결 회귀를 검증하라. 각 단계의 파일을 다음 단계가 읽어라. 이미 확정된 요구이므로 재인터뷰 없이 진행하라. shape 결정은 decisions.md, spec은 SPEC.md, ticket은 tickets.md, build 검증은 evidence.md에 기록하라. tracker 게시 요청은 없으며 tickets.md는 로컬 초안이다. 기술 최신성 조사는 필요 없다: Python 3.12 표준 라이브러리 고정. 외부 검색/설치/네트워크/프로덕션/하위 agent/UI/Codex 호출/ git 변경은 금지. keep.txt 및 모든 기존 파일을 보존하라.
확정 요구: 공개 stateless delivery quote CLI. shipment가 weight 검증/가격을 소유하고 CLI adapter가 JSON/exit 변환을 소유. python quote.py 1은 exit 0 stdout JSON {"total":5000}. 정수 1..5는 5000, 6..10은 8000. 0,11,비정수,인수누락은 exit 2, stdout 비어 있음, stderr JSON {"error":"INVALID_WEIGHT","retryable":false}, traceback 없음. 실패 다음 유효 실행은 성공. Python process의 공개 행동을 테스트하라. 성능 SLO/인증/저장/외부 서비스는 해당 없음. 작은 한 모듈이면 충분하다. 제품 구현은 quote.py 및 test_quote.py만, 문서는 위 네 파일만 쓸 수 있다. 결정을 모든 단계에서 유지하고 요구사항과 테스트 증거를 연결하라. 마지막 보고는 실제 실행/NOTRUN을 구분하라. 도구 거절은 우회하지 말고 남은 경계를 명시하라.
