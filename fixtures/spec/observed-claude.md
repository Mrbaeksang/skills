# 개인용 메모 CLI 최소 명세

명세를 답변으로 작성했습니다. 파일 생성, 구현, 외부 게시는 하지 않았습니다. 표기는 **[확정]** 사용자 결정, **[제안]** 에이전트 제안(미확정)으로 구분합니다.

## 1. 목표와 범위
- **목표 [확정]:** 개인 사용자가 명령줄에서 메모를 추가하고 전체 목록을 조회한다.
- **기술 [확정]:** Python 표준 라이브러리만 사용한다.
- **저장 위치 [확정]:** 현재 디렉터리의 `notes.json`(UTF-8 JSON)을 사용한다.
- **비목표 [확정]:** 삭제, 동기화, 로그인, 네트워크 기능은 범위 밖이다.

## 2. 요구사항과 수용 기준

| ID | 요구 [확정] | 수용 기준 (입력 → 관찰 결과) |
|---|---|---|
| R1 | `notes add TEXT`는 공백을 제거한 메모를 저장한다 | **AC1:** `notes.json`이 없을 때 `notes add "우유 사기"` → 파일이 생성되고, UTF-8 JSON으로 파싱되며, `우유 사기`가 들어 있다.<br>**AC2:** `notes add "  우유 사기  "` → 앞뒤 공백 없이 `우유 사기`로 저장된다. |
| R2 | 저장 후 ID를 반환한다 | **AC3:** 성공한 `add`의 출력에 ID가 있고, 그 ID가 저장된 메모의 ID와 일치한다. |
| R3 | 빈 입력은 오류로 거절하고 기존 파일을 보존한다 | **AC4:** `notes add ""`와 `notes add "   "` → 오류가 표시된다. `notes.json`이 있었다면 실행 전후 바이트가 같고, 없었다면 새로 생기지 않는다. |
| R4 | `notes list`는 생성 순서로 모든 메모를 보여준다 | **AC5:** A, B, C 순서로 추가한 뒤 `notes list` → 세 메모가 A, B, C 순서로 모두 표시된다. |
| R5 | 파일이 없으면 빈 목록이다 | **AC6:** `notes.json`이 없을 때 `notes list` → 오류 없이 메모 0건으로 표시된다. |
| R6 | 잘못된 JSON은 오류를 표시하고 원본을 보존한다 | **AC7:** `notes.json` 내용이 `{broken`일 때 `notes list` → 오류가 표시되고 실행 전후 바이트가 같다.<br>**AC8:** 같은 파일 상태에서 `notes add "x"` → 오류가 표시되고 실행 전후 바이트가 같다. |
| R7 | 저장 위치는 현재 디렉터리다 | **AC9:** 디렉터리 D1에서 메모를 추가한 뒤 빈 디렉터리 D2에서 `notes list` → 메모 0건이며, D1의 파일은 변하지 않는다. |
| R8 | 표준 라이브러리만 사용한다 | **AC10:** 서드파티 패키지를 설치하지 않은 환경에서 AC1~AC9가 통과하고, 코드의 import가 모두 표준 라이브러리다. |
| R9 | 범위 밖 기능을 넣지 않는다 | **AC11:** CLI에 삭제, 동기화, 로그인 명령이 없고, 코드에 네트워크 호출이 없다. |

AC2는 "공백 제거"를 앞뒤 공백 제거로 해석한 기준이므로 미결정 U1에 따라 달라질 수 있습니다. AC8은 "잘못된 JSON은 원본을 보존한다"는 결정을 `add`에도 적용한 것입니다.

## 3. 제안 사항 [제안]
구현 전에 뒤집어도 위의 확정 요구와 충돌하지 않는 항목입니다.
- **종료 코드:** 성공은 0, 오류는 0이 아닌 값으로 하고, 오류 메시지는 stderr로 출력한다.
- **데이터 형식:** `{"id": ..., "text": ...}` 객체의 JSON 배열로 하고, 생성 순서는 배열 순서로 유지한다.
- **ID:** 파일 안에서 유일한 증가 정수로 한다.
- **JSON 인코딩:** `ensure_ascii=False`로 저장해 한글을 파일에서 그대로 읽을 수 있게 한다.
- **쓰기 방식:** 임시 파일에 쓴 뒤 `os.replace`로 교체해 쓰기 실패 시에도 원본을 보존한다.

## 4. 미결정 사항

| ID | 항목 | 비고 |
|---|---|---|
| U1 | 공백 제거 범위 | 앞뒤 제거로 추정했다. 메모 내부 공백 처리는 정해지지 않았다. |
| U2 | 성능 수치 | **미결정(사용자 명시).** 수용 기준에 넣지 않았다. |
| U3 | ID 형식과 `add`, `list` 출력 형식 | 3절 제안이 채택되지 않으면 AC3과 AC5의 검증 방식이 달라진다. |
| U4 | JSON 문법은 맞지만 구조가 다른 파일(예: `{}`) | R6 적용 여부가 미정이다. 같은 오류 처리와 원본 보존을 권장한다. |
| U5 | `notes add`에 인자가 없을 때와 `TEXT`가 여러 단어일 때 | 인자 누락을 빈 입력과 같이 처리할지, 따옴표 없는 여러 인자를 합칠지 미정이다. |
| U6 | 동시 실행 | 여러 프로세스가 동시에 쓸 때의 동작이 미정이다. |
| U7 | 파일 읽기·쓰기 권한 오류 | 메시지와 동작이 미정이다. 원본 보존 원칙을 적용하도록 권장한다. |
| U8 | `notes` 명령 제공 방식과 최소 Python 버전 | 설치 또는 실행 방식이 미정이다. |

## 5. 결과와 검증
- **결과:** 명세 작성만 완료했으며 제품은 구현되지 않았습니다.
- **수행한 검증:** 문서 수준에서 확정 결정이 R1~R9와 AC1~AC11에 빠짐없이 연결되는지, 서로 모순되지 않는지 점검했습니다. 누락이나 모순은 없었고, 해석이 필요한 부분은 U1과 AC8뿐입니다.
- **NOTRUN:**
  - 모든 AC의 실제 실행 (구현체 없음)
  - 대시보드 작업 보고 (이 세션에 명령 실행 도구가 없음)
- **남은 문제:** U1~U8은 미결정이며, 이 중 구현 전에 정하는 편이 좋은 항목은 U1, U3, U5입니다.
