# 개인용 메모 CLI 최소 명세

명세는 작성했지만 구현과 제품 검증은 하지 않았습니다. 확정 결정 밖의 세부 사항은 추정(`A-*`)이나 제안(`P-*`)으로 표시했고, 이에 의존하는 수용 기준은 조건부입니다.

## 1. 범위

**목표(확정):** 한 사용자가 터미널에서 메모를 추가하고 전체 목록을 볼 수 있게 한다.

**비목표(확정):** 삭제, 동기화, 로그인, 네트워크 기능

**해당 없음:**
- 인증·권한: 로그인 없는 개인용 CLI이므로 actor는 로컬 사용자 1명이다.
- 외부 API·retry: 네트워크 기능이 없다.
- 로깅·관측성: 입력 결정에 요구가 없다.

## 2. 확정 요구

| ID | 요구 |
|---|---|
| R-01 | Python 표준 라이브러리만 사용한다. |
| R-02 | 저장 위치는 현재 디렉터리의 `notes.json`이고, 형식은 UTF-8 JSON이다. |
| R-03 | `notes add TEXT`는 공백을 제거한 비어 있지 않은 메모를 저장하고 ID를 반환한다. |
| R-04 | 빈 입력은 오류로 거절하고 기존 파일을 보존한다. |
| R-05 | `notes list`는 모든 메모를 생성 순서로 보여준다. |
| R-06 | `notes.json`이 없으면 `notes list`는 빈 목록으로 처리한다. |
| R-07 | JSON이 잘못되었으면 오류를 표시하고 원본을 보존한다. |

## 3. 추정과 제안

아래 항목은 확정 결정이 아닙니다.

| ID | 구분 | 내용 |
|---|---|---|
| A-1 | 추정 | "공백 제거"는 앞뒤 공백 제거(`str.strip()`)이며, 내부 공백은 유지한다. |
| A-2 | 추정 | R-07은 `list`와 `add`에 모두 적용되므로, 잘못된 파일에는 `add`도 저장하지 않는다. |
| A-3 | 추정 | 파일이 없을 때 `add`를 실행하면 새 파일을 만들어 저장한다. |
| A-4 | 추정 | ID는 파일 안에서 메모마다 고유하다. |
| P-1 | 제안 | 파일 구조는 `[{"id": 1, "text": "메모"}]`이고, 배열 순서가 생성 순서다. |
| P-2 | 제안 | ID는 1부터 시작하는 정수이며, 기존 최댓값에 1을 더해 부여한다. |
| P-3 | 제안 | `add`는 성공 시 stdout에 ID만 출력한다. `list`는 한 줄에 `<id>\t<text>`로 출력하고, 빈 목록이면 아무것도 출력하지 않는다. |
| P-4 | 제안 | 성공 시 exit code는 `0`, 오류 시 `1`이며 오류 메시지는 stderr로 출력한다. |
| P-5 | 제안 | `TEXT` 인자가 없으면 빈 입력과 같은 오류로 처리한다. |
| P-6 | 제안 | UTF-8로 읽을 수 없거나 P-1 구조가 아닌 파일도 R-07과 같이 처리한다. |
| P-7 | 제안 | 임시 파일에 쓴 뒤 `os.replace`로 교체해, 쓰기 실패 시에도 기존 파일을 보존한다. |
| P-8 | 제안 | 오류로 끝난 `add`와 모든 `list`는 파일을 새로 만들지 않는다. |

## 4. 수용 기준

### 확정 결정만으로 판정

| ID | 요구 | 입력·조건 | 기대 결과 |
|---|---|---|---|
| AC-01 | R-01 | 서드파티 패키지가 없는 새 venv에서 `add`, `list` 실행 | import 오류 없이 동작한다. |
| AC-02 | R-02 | 디렉터리 A에서 `notes add "메모"` 실행 | `A/notes.json`이 생기거나 갱신된다. |
| AC-03 | R-02, R-03 | `notes add "한글 메모 ✓"` 실행 | 파일을 UTF-8로 디코딩해 JSON으로 파싱할 수 있고, 같은 텍스트가 들어 있다. |
| AC-04 | R-03 | `notes add "  hello  "` 실행 | 저장된 텍스트가 `hello`이고, 출력에 ID가 포함된다. |
| AC-05 | R-04 | 기존 `notes.json`이 있을 때 `notes add ""`와 `notes add "   "` 실행 | 각각 오류가 표시되고, 파일 바이트가 실행 전과 같다. |
| AC-06 | R-05 | `first`, `second`, `third`를 순서대로 추가한 뒤 `notes list` 실행 | 세 메모가 모두 추가한 순서대로 표시된다. |
| AC-07 | R-06 | `notes.json`이 없는 디렉터리에서 `notes list` 실행 | 오류 없이 메모가 하나도 표시되지 않는다. |
| AC-08 | R-07 | `notes.json` 내용이 `{broken`일 때 `notes list` 실행 | 오류가 표시되고, 파일 바이트가 실행 전과 같다. |
| AC-09 | R-07 | `notes.json`이 0바이트일 때 `notes list` 실행 | AC-08과 같다. |

### 조건부

| ID | 전제 | 입력·조건 | 기대 결과 |
|---|---|---|---|
| AC-10 | A-1 | `notes add "a  b"` 실행 | 저장된 텍스트가 `a  b`다. |
| AC-11 | A-2 | `notes.json` 내용이 `{broken`일 때 `notes add "x"` 실행 | 오류가 표시되고, 파일 바이트가 실행 전과 같다. |
| AC-12 | A-3 | `notes.json`이 없을 때 `notes add "x"` 실행 | 파일이 생성되고 메모 1건이 저장된다. |
| AC-13 | A-4, P-2 | 빈 상태에서 메모 2건 추가 | ID로 `1`, `2`가 반환된다. |
| AC-14 | P-1 | 메모 2건 추가 후 파일 파싱 | 추가 순서대로 `id`, `text`를 가진 객체 2개의 배열이다. |
| AC-15 | P-3 | 메모 2건 추가 후 `notes list` 실행 | stdout이 `1\t...`, `2\t...` 두 줄이다. |
| AC-16 | P-4 | AC-04, AC-05, AC-08 시나리오 실행 | 성공은 exit `0`이고, 오류는 exit `1`이며 메시지가 stderr로 출력된다. |
| AC-17 | P-5 | 기존 파일이 있을 때 `notes add` 실행 | 오류가 표시되고, 파일 바이트가 실행 전과 같다. |
| AC-18 | P-6 | 파일이 `{}`이거나 UTF-8이 아닌 바이트일 때 `add`, `list` 실행 | 오류가 표시되고, 파일 바이트가 실행 전과 같다. |
| AC-19 | P-7 | 저장 단계에 쓰기 실패를 주입 | 오류가 표시되고, 기존 파일 바이트가 실행 전과 같다. |
| AC-20 | P-8 | 파일이 없는 디렉터리에서 `notes add ""`와 `notes list` 실행 | `notes.json`이 생성되지 않는다. |

**검증 환경:** Windows PowerShell에서 임시 디렉터리를 만들어 실제 CLI를 실행한다. 파일 보존 여부는 실행 전후의 바이트를 비교해 판정한다.

## 5. 미결정 사항

| 항목 | 영향 | 재개 조건 |
|---|---|---|
| 성능 수치 | 성능 수용 기준을 두지 않는다. | 메모 수와 응답 시간 목표가 정해지면 요구와 수용 기준을 추가한다. |
| Python 최소 버전 | 사용 가능한 표준 라이브러리 API와 검증 환경 | 구현 전 지원 버전을 정한다. |
| `notes` 명령 제공 방식 | 실행·배포 구조(`pyproject.toml` entry point, 스크립트 등) | 구현 전 방식을 정한다. |
| 동시 실행 처리 | 여러 프로세스가 동시에 `add`하면 메모가 유실될 수 있으며, 현재 수용 기준에 포함되지 않는다. | 동시 실행을 지원하기로 하면 잠금 요구와 수용 기준을 추가한다. |

`A-*`와 `P-*`도 채택 전까지는 미확정입니다. 다른 값으로 결정되면 해당 조건부 수용 기준을 함께 수정합니다.

## 6. 작성 상태

- **결정 추적:** 범위 결정은 비목표에, 나머지 확정 결정은 R-01~R-07과 AC-01~AC-09에 반영했고, 성능 수치는 미결정 사항에 남겼습니다.
- **제품 검증:** AC-01~AC-20은 모두 NOTRUN입니다.
- **산출물:** 요청대로 파일 생성, 구현, 외부 게시는 하지 않았습니다.
