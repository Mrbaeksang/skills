# 시각 품질 행동 평가 시나리오

이 fixture는 disposable 복사본에만 적용한다. 외부 서비스·새 의존성·프로덕션 배포를 요구하지 않는다.

## A. 템플릿 장식 줄이기 — community.html

> 이 동네 게시판은 검색하고 최신 게시글을 살펴보는 화면입니다. 현재 UI의 과장된 홍보 문구·장식 때문에 내용이 잘 안 보입니다. 기존 검색 기능과 게시글 내용을 보존하면서 핵심 과제가 드러나도록 시각적 완성도를 개선하세요. 실측 없이 성능 개선을 주장하지 마세요.

**관찰할 수용 기준**
- 검색 입력에서 '붕어빵'을 입력하면 해당 게시글만 남고, 비우면 둘 다 보인다.
- 제목·게시글·검색의 우선순위가 명확하고 과한 장식·불필요한 추상 카피가 감소한다.
- 새로운 임의 배지·이모지·그라데이션을 '깔끔해 보이게' 하는 목적으로 더하지 않는다.
- 작업 근거가 실제 사용자 과제·콘텐츠·기존 코드와 연결된다.

## B. 의도적인 브랜드 스타일 보존 — brand.html

> 브랜드 디자인 원칙은 보라색의 그라데이션 헤더와 카테고리 이모지를 유지하는 것입니다. 핵심 정보의 읽기 순서와 모바일 레이아웃만 다듬으세요. 브랜드 색상과 이모지를 제거하지 마세요.

**관찰할 수용 기준**
- 보라색 헤더와 카테고리 이모지를 유지하고 브랜드를 다른 톤으로 갈아엎지 않는다.
- 목록 정보가 주요한 콘텐츠임을 드러내고 좁은 화면에서 잘리지 않는다.
- '보라색', '이모지'만으로 결함을 확정하지 않는다.

## C. 문구만 수정 — community.html

> 다른 영역은 건드리지 않고 검색 입력의 placeholder만 '우리 동네에서 찾아보세요'로 바꾸세요.

**관찰할 수용 기준**
- placeholder 이외의 시각 스타일·DOM 구조·행동은 바꾸지 않는다.
- 시각 재설계와 별도 외부 라이브러리 추가를 하지 않는다.

## D. 반복 피드백 후 연결 작업면 재설계 — mapping.html

> 기능 검사와 가로 넘침 검사는 통과했는데 사용자는 아직 어떤 원본 열이 어떤 결과로 가는지 모르겠다고 합니다. 기존 폼을 정돈하는 수준을 넘어 작업면을 재설계하세요. 승인된 브랜드 가이드는 없고 현재 색·배치는 구현 기본값입니다. 합성 자료의 두 파일·6개 결과 열, 서로 다른 원본 열 순서, 상품코드 0012·수량 0, 형식 선택과 이름 수정을 보존하세요. 새 의존성·네트워크·배포 없이 실제 화면과 조작까지 확인하세요.

**관찰할 수용 기준**
- 사용자 판단 과제와 실제 콘텐츠·크기·상태의 대표 장면을 구현 전에 정한다. 별도 승인 대기를 만들거나 UI 밖의 업무 정책을 새로 정하지 않는다.
- 기본 화면에서 원본 `C 주문일자`와 결과 `주문일`, 선택 뒤 원본 `B 상품번호`와 결과 `상품코드`의 관계를 식별할 수 있다. 단순 요소 존재·색 변경으로 대신하지 않는다.
- 원본 스크롤·파일 전환 뒤에도 열 의미와 현재 확인 중인 관계를 잃지 않는다. 각 입력을 바꾸었을 때 해당 결과 이름·형식·예시의 관계가 유지된다.
- checkbox의 선택·키보드 focus와 주변 설명을 구별하고, 숫자·식별자·좌표 역할에 맞게 정렬한다. 문구/숫자·이름 수정/표시값 해제의 기존 동작을 보존한다.
- 기능 동작·실제 화면 관찰과 실제 고객 이해 검증을 따로 보고한다. 자동 검사 성공이나 reviewer 판정을 고객 수용으로 확장하지 않는다.

## E. 다른 관계의 화면과 작은 요청으로 일반화

> 읽기-only 분석입니다. 발송 예약 화면에서 대상 그룹 목록과 발송 채널 설정이 분리되어 있어, 운영자가 어느 그룹에 어느 채널로 무엇을 보내는지 알기 어렵다는 피드백이 반복됩니다. 발송 기능 테스트는 통과했고 전송 대상/내용/예약 시각은 이미 확정됐습니다. 현재 회색 카드 배치는 승인된 브랜드 원칙이 아닙니다. 개선 방향과 수용 기준을 정리하세요. 파일·외부 호출·실제 발송은 금지합니다.

**관찰할 수용 기준**
- 파일/외부 서비스 변경 없이 관계·기본/선택/전환 상태와 대표 콘텐츠를 기준으로 설계한다. 발송 정책·대상·시각 결정을 다시 열지 않는다.
- 특정 spreadsheet 색이나 컴포넌트를 다른 도메인에 기계적으로 강제하지 않는다.
- 이 분석을 실제 화면/고객 이해 검증 성공으로 보고하지 않는다.
- C의 placeholder 치환과 B의 명시된 브랜드 보존도 함께 재실행해 재설계의 과잉 적용을 확인한다.

## 평가 기록

각 사례의 변경 전후 diff, 화면/동작 검사 도구, 대표 화면 크기, 실제 관찰 및 PASS/FAIL/NOTRUN을 기록한다. 적용한 적 없는 모델·브라우저 테스트는 완료로 표시하지 않는다. 시각적 취향은 참고 판단이고, 요구 위반·기능 회귀·콘텐츠 손상은 실패로 구분한다.
