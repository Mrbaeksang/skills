# 한 페이지 설명 문서 제작

## 글 구성

1. **읽고 나서 할 일부터.** 독자가 알아야 할 결론과 결정·행동을 제목 다음 한두 문장에 둔다. 구현 순서가 핵심이면 개발 로드맵을 바로 이어 넣고, 첫 작업의 범위와 눈으로 확인할 완료 기준을 강조한다. 비교나 설명이 목적이면 그 목적에 맞는 핵심 비교나 흐름부터 보여준다.
2. **상태와 경계.** 현재 확인된 동작, 합의된 변경, 제안이나 확인 중인 항목을 짧은 문구로 구분한다. 추측이나 계획을 실제 동작처럼 쓰지 않는다. 케이스마다 어디까지 되고 어디서 막히는지 실제 입력 또는 보이는 결과로 설명한다.
3. **표현은 관계에 맞춰 선택.** 순서는 번호 목록, 갈라졌다 모이는 경로는 나뭇가지 도식, 케이스별 차이는 짧은 표를 쓴다. 공통 경로는 굵은 선으로, 구현에 앞서 확인할 조건은 점선과 이유로 표시한다. 제외된 경로나 제거 후보는 결과선과 분리한다. 표와 도식이 같은 내용을 반복하면 한쪽을 줄인다.
4. **본문은 독자의 언어로.** 코드·도구명보다 “누가 무엇을 하면 어떤 결과가 보이는지”를 먼저 쓴다. 판단에 필요한 제약은 본문에 남긴다. 세부 코드·정확한 요청 예시·출처는 문서 끝의 참고로 옮긴다.

## HTML 구성과 확인

- 템플릿의 자리표시자를 채우고, 읽는 데 필요 없는 섹션, 샘플 행, 목차 링크는 함께 삭제한다. 핵심 순서·도식·케이스는 처음부터 볼 수 있게 두고 자세한 근거만 `details`로 접는다. 본문 가독성을 해치는 장식 번호, 배지, 과도한 강조는 줄인다.
- 요청된 브랜드와 글꼴이 있으면 따른다. 기본 틀은 밝은 배경, 짙은 글자, 변경 경로에 파랑, 제거 후보에 버건디를 사용한다. 색에 의미가 있으면 글자로도 뜻을 적는다. 글꼴과 자산은 제공되었거나 사용 권한이 확인된 파일만 포함한다.
- 팀 공유용 파일은 외부 CSS·JS·폰트를 불러오지 않고 브라우저에서 단독으로 열린다. 자산이 필요하면 파일에 포함하고, 근거 링크는 선택적으로 열리게 한다. 외부 공유본에는 공개 가능한 예시와 자료만 넣으며 숨겨진 HTML, 첨부 자산과 링크도 확인한다.
- 완성 HTML을 데스크톱·모바일에서 열어 첫 화면의 결론, 줄바꿈, 가로 넘침, 도식의 선과 글자, 링크·접기/펼치기를 확인한다. 기존 문서의 일부만 수정했다면 영향 범위에 집중한다. 전달할 때 파일 위치와 실제 확인 범위를 짧게 적는다.
