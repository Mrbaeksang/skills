# 검증 기준 변경 검토

테스트 삭제·skip, assertion 축소, CI 검사 제외, snapshot 변경, timeout·허용 오차 확대, 오류를 삼키는 변경이 있을 때 읽는다.

1. 관련 diff를 목록화한 뒤 원래 보호하던 계약과 실패 조건을 읽는다. 목록에 있다는 사실만으로 finding을 만들지 않는다.
2. 완화가 원래 실패를 숨기는지, 제품 계약 변경·측정·대체 검증으로 정당화되는지 확인한다. 커밋 메시지의 주장과 실제 근거를 구분한다. 이름·주석·생성된 snapshot만으로 근거를 확정하지 않는다.
3. 근거 없는 완화는 영향, head 기준 위치, 원래 보호 계약과 필요한 수정 방향을 보고한다. 같은 원인의 여러 snapshot이나 설정 변경은 하나로 묶는다. 근거가 불충분하면 확인이 필요한 위험으로 구분한다.
4. 리뷰-only에서는 테스트·CI를 고치거나 상태를 변경하지 않는다. 수정 권한이 있는 부모 작업에는 원래 보호를 복원하거나 정당한 대체 검증을 요구한다. 통과를 위해 유효한 실패를 제거하지 않는다.

정당한 계약 변경과 측정에 따른 timeout 조정을 자동 결함으로 취급하지 않는다. 평가 기준과 결과가 함께 바뀌면 기준이 결과를 본 뒤 낮아졌는지도 확인한다.
