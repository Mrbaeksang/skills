# Domain

입력은 관련 use case·기존 용어·코드와 아직 결정되지 않은 도메인 질문이다. 제품 결정은 대신 확정하지 않는다.

1. 기존 glossary·타입·테스트와 실제 사례의 용어를 대조한다. 같은 말이 다른 의미인지, 같은 개념을 다른 이름으로 쓰는지 확인한다.
2. 정상 사례와 충돌·실패·복구 사례로 entity/value, 식별자, 불변식, 허용/거절 상태 전이를 구체화한다. 모든 과제에 DDD 패턴을 채우지 않는다.
3. 모듈별 데이터 소유자·권한·공개 계약·transaction 경계를 정한다. 도메인 오류의 의미와 공통 handler의 외부 변환 책임을 분리한다. 타 모듈 저장소 직접 접근은 계약 문제로 확인한다.
4. 결과는 용어·불변식·상태·경계와 사례, 확정/제안/미정으로 반환한다. 기존 결정을 재인터뷰하지 않고 중대한 미정만 묶어 질문한다. 루트 용어집·ADR을 자동 생성하지 않는다. 기존 문서 갱신이나 중요한 결정 인계가 필요하면 [작업 기록](../agent-records.md)으로 기존 원본·관련 코드·소비 작업을 연결한다.

종료 조건은 관련 use case가 모델로 설명되거나 설명되지 않는 지점이 명시된 상태다. 구현·전체 구조 변경은 포함하지 않는다.
