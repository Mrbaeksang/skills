# 실제 요청으로 검증

## 시험 전에 고정할 것

대상 스킬 원본·호스트·모델/설정, 사용자 요청·원자료·기대 결과·권한을 고정한다. 시간과 실행 횟수는 변경 위험과 사용자의 범위에 맞춰 정한다. 기존 실패 trace가 같은 계약과 환경을 설명하면 재사용한다. 비교할 baseline이 없거나 전역 지침을 격리할 수 없으면 그 한계를 밝히며, 없는 무스킬 대조군을 만들었다고 보고하지 않는다.

대표 정상 요청, 실제 실패 조건, 비슷하지만 적용하면 안 되는 요청과 수정에 쓰지 않은 변형을 선택한다. 대화 스킬은 부분 답변·조건 변경·위임·중단을 필요한 만큼 이어간다. 상태를 저장하는 스킬은 새 세션에서 원본을 다시 읽는지도 확인한다. 모든 스킬에 같은 시험 수나 거대한 조합표를 강제하지 않는다.

## 세 층의 증거

| 층 | 실행자에게 주는 것 | 확인할 것 |
|---|---|---|
| 발견 | 자연스러운 요청과 호스트가 실제 제공하는 후보 목록 | 적합한 진입점 선택, 비적용 요청의 과잉 호출 |
| 절차 | 지정 스킬·원자료·권한 | 본문/필요 참조의 실제 읽기, 결과를 다음 행동에 반영 |
| 결과 | 같은 과제를 수행할 수 있는 격리 작업 공간 | 산출물 내용·코드/파일 diff·실제 명령/UI/API 효과와 회귀 |

실행자에게 평가 체크리스트, 의도한 수정, 이전 평가 결론을 정답 힌트로 주지 않는다. 과제 자체에 원래 포함된 사용자 기준은 유지한다. 현재 세션이 스스로 만든 정답을 반복하는 것보다 새 세션에서 실행해 판단한다. 별도 실행이 불가능하면 정적 검토까지만 하고 실제 행동은 NOTRUN으로 남긴다.

새로 만든 스킬은 **그 스킬을 소비하는 다른 실제 요청**에도 사용한다. 스킬 파일이 존재하거나 설명에 키워드가 있다는 것으로 제작 성공을 판정하지 않는다. 생성한 스크립트는 실제 입력으로 실행하고, 깨진 입력·기존 파일 보존처럼 관련된 경계를 확인한다. 제공된 deterministic validator가 있으면 재사용한다.

## 판정과 개선

실제 trace와 산출물을 읽어 기대 결과별 PASS/FAIL/NOTRUN을 남긴다. 실행자의 자기 보고는 근거와 대조한다. 호출 성공과 과제 성공, 설치 성공과 실제 실행 성공을 합치지 않는다. 문체·디자인처럼 주관성이 있는 결과도 요청의 제약·비교 산출물에 근거해 검토하며 점수만으로 품질을 확정하지 않는다.

실패가 과제·평가 기준의 오류인지 먼저 확인한다. 기준 변경이 필요하면 이유와 이전 판정을 보존하고 새 버전의 과제로 구분한다. 결과를 본 뒤 성공에 맞춰 기대값을 바꾸지 않는다. 원인별로 좁게 수정한 뒤 영향받는 사례와 아직 수정에 쓰지 않은 변형을 실행한다. 단일 trial을 통계적 개선이나 자동 호출 보장으로 표현하지 않는다.

스킬 추가로 결과가 좋아지지 않거나 비용·과잉 호출이 더 커지면 축소·기존 스킬 통합·미채택을 제안한다. 횟수/시간 한도에 도달하면 확보한 증거와 남은 실패를 보고하며 무한 최적화하지 않는다. 임시 평가 파일은 허용된 작업 공간에 보존하고 공개 보고서나 사용자 설정 변경을 자동으로 만들지 않는다.
