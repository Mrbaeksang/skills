# Craft

입력은 사용자의 목표, 작업 대화·산출물, 기존 스킬 또는 실패 기록이다. 먼저 [공통 실행 계약](references/execution-contract.md)을 읽는다. 작업 방식을 재사용하거나 스킬 자체를 개선하는 요청에 적용한다. 일반 개발 중 발견한 실수 하나를 근거로 스킬 제작을 자동 시작하지 않는다.

1. **필요성 판정.** 현재 작업 방식과 기존 지침·스킬·도구를 확인하고 아래에서 가장 작은 해법을 선택한다. 이미 제공된 목표·사례는 재사용하고, 결과를 바꿀 중요한 빈칸만 추천/대안과 함께 묶어 묻는다. 사용자가 명시적으로 새 스킬을 요청했는데 다른 형태가 더 적합하면 이유를 설명하고 그 산출물을 몰래 대체하지 않는다.

   | 필요한 것 | 기본 해법 |
   |---|---|
   | 이번 요청 한 번의 처리 | 현재 작업 수행; 스킬 불필요 |
   | 특정 프로젝트의 위치·규칙 | 기존 프로젝트 지침/설정 |
   | 반복되는 기계적 변환·검사 | 기존 자동화 또는 작은 스크립트 |
   | 기존 스킬과 같은 입력·판단·출력 | 기존 스킬의 해당 조건 수정 |
   | 여러 작업에서 재사용할 독립된 판단·절차 | 신규 스킬 |

2. **행동 계약.** [설계](references/design.md)를 읽고 실제 요청, 적용/비적용 조건, 필요한 근거·도구, 관찰 가능한 결과와 완료 경계를 정한다. 실제 사용에서 모자란 지식·판단만 담고 모델이 이미 잘하는 일반론을 추가하지 않는다. 제안/분석-only이면 계약과 추천을 채팅으로 반환한다.
3. **제작·수정.** 쓰기가 허용되면 지정된 경로와 기존 원본을 수정한다. 기존 스킬 개선은 파일·참조·실행 기록에서 실패 지점을 확인하고 해당 의미의 원본을 바꾼다. 새 스킬은 이름/설명과 필요한 본문부터 만들며 비어 있는 디렉터리·예시·보고서를 생성하지 않는다. 코드·스크립트가 필요할 때만 실제 실행 환경에 맞춰 추가하고 실행 확인한다. 저장소 변경은 [작업 공간 수명주기](references/workspace-lifecycle.md)를 따른다.
4. **검증·축소.** [평가](references/evaluate.md)를 읽고 요청된 호스트에서 실제 과제를 수행한다. 호출, 참조 적용, 결과를 따로 판정하고 실패 원인에 맞춰 최소 수정한다. 형식 검사는 설치 가능성의 증거이며 좋은 판단의 증거가 아니다. 제공되지 않은 실행 도구·권한은 미검증으로 남긴다.
5. **전달.** `판단 / 바뀐 행동 / 실제 검증과 남은 한계 / 사용 예시`를 채팅에 간결히 반환한다. 새로운 스킬 없이 끝난 것도 유효한 결과다. 필요한 결정은 [기존 작업 기록](references/agent-records.md)에 연결하며 보고 MD/HTML·평가 대시보드는 요청된 경우만 만든다. 설치·게시·버전 배포는 요청 범위에 포함된 경우에만 수행한다.

매 단계 재승인이나 특정 평가 프레임워크·모델·서브에이전트를 필수로 만들지 않는다. 호출 도구 대신 참조를 읽고 적용했으면 실제 방식을 그대로 보고한다. 스킬의 원본과 생성된 설치본을 구분하고, 기존 사용자의 다른 설정을 덮어쓰지 않는다.
