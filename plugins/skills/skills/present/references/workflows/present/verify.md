# 발표자료 수용 검수

원자료의 필수 메시지·사실·예시·출처와 실제 청중에게 보이는 장의 범위를 먼저 대조한다. 행사 일부를 맡은 발표라면 첫 장부터 마지막 장까지 요청된 구간으로 끝나는지 확인한다. 새 사례를 원래 발표의 주장과 혼동하거나 수치를 임의 변경하지 않았는지 확인한다. 발표용/읽기용·제공 기능·변경 영향으로 아래 검사의 적용 범위를 정한다. 신규/전체 개선은 전체를, 국소 수정은 영향받는 장과 흐름을 검수한다. 공통 스타일·폰트·조작 변경은 전체 소비 범위를 확인한다. 유효한 기존 증거는 재사용하되 없으면 필요한 검사를 실행한다. 필요한데 실행하지 못한 검사는 NOTRUN, 제공하지 않아 해당 없는 기능은 적용 제외로 구분한다. 검사를 채우기 위해 기능을 추가하지 않는다.

1. **실제 전달.** 최종 HTML을 다른 빈 폴더로 복사해 직접 연다. 네트워크를 끈 새 context/캐시 없는 조건에서 폰트·이미지·스크립트·본문이 보이는지 확인한다. 폰트는 @font-face 자산과 로딩 완료를 확인하고 실제 렌더링도 본다. font-family 문자열이나 폰트 없이도 true가 될 수 있는 단일 check 결과만으로 내장 서체 사용을 판정하지 않는다. 요청/console 오류를 확인하고 하드코딩된 로컬 경로·외부 runtime 의존성을 검사한다. 단순 파일 생성과 offline PASS를 구분한다.
2. **시각 검토.** 목표 화면과 작은 노트북 높이에서 해당 범위의 장/구역을 렌더링한다. 전체 검수는 contact sheet로 리듬·구도 반복·일관성도 본다. 각 장/구역의 실제 크기 캡처로 글자·이미지·줄바꿈·대비·clipping을 읽는다. DOM overflow 검사만으로 시각 품질을 판정하지 않는다. 문제 장은 수정해 다시 확인한다.
3. **좁은 화면.** 모바일 공유를 의도하면 세로 화면에서 읽기 모드/재배치·버튼을 확인한다. canvas 전체가 들어온다는 이유로 읽기 PASS를 주지 않는다. 작은 화면이 범위 밖이면 제한을 보고한다.
4. **사용 흐름.** 장 이동형이면 이전/다음·직접 장 링크·새로고침·키보드를, 연속 읽기형이면 스크롤·읽는 순서·제공한 anchor를 확인한다. 목차·fullscreen 등 추가 조작은 제공한 경우 검증한다. 장 전환/모션이 있으면 빠른 연속 입력, animation 중 이동, 재진입에서 위치·내용·모션 상태를 확인한다. 전환이 끝난 캡처만 보지 말고 도중의 스크롤바·콘텐츠 폭·줄바꿈 변화도 관찰한다. 흔들림이 있으면 프레임별 geometry 등 구분 가능한 증거로 원인을 좁히고 같은 입력으로 재검증한다. 링크·입력 field의 기본 조작과 focus를 보존한다.
5. **대체 표시.** 모션이 있으면 reduced-motion에서 본문과 조작을 확인한다. 인쇄를 제공하면 모든 장과 최종 reveal 내용이 나오는지 실제 print/PDF를 확인한다. print CSS가 있다는 사실만으로 PDF 성공을 주장하지 않는다.
6. **완성도.** 청중이 핵심을 빨리 파악하는지, 읽을 수 있는지, 그래픽이 실제 내용을 설명하는지, 구도와 모션에 이유가 있는지 판정한다. 장식의 개수나 취향 점수로 품질을 대신하지 않는다. 초안과 최종안을 같은 조건으로 비교하고 확인된 개선과 취향 선택을 구분한다.

가림 처리한 원문은 최종 배포 파일에서 요청한 쪽과 순서, 읽을 수 있는 크기를 확인한다. 확대 보기를 제공했다면 첫·마지막 쪽 이동과 닫은 뒤 발표 위치 복귀를 실행한다. 가려진 값은 화면과 내장 원본·텍스트·링크·메타데이터에서도 복구되지 않는지 확인한다.

폰트는 새 문구의 한글·영문·숫자·기호도 확인한다. 가능하면 브라우저의 실제 rendered font 정보로 누락 glyph의 시스템 fallback을 구분한다. 로딩 완료만으로 모든 글자를 선택한 폰트가 그렸다고 판단하지 않는다.

실패가 있으면 영향받는 내용·디자인·구현을 고치고 관련 장과 전체 흐름을 다시 본다. 실행 환경 때문에 막히면 통과로 바꾸지 말고 결과 파일과 미검증 범위를 전달한다. 생성자의 완료 선언만으로 검수를 끝내지 않는다.
