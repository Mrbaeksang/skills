# Verify

입력은 수용 기준·변경 범위·테스트 결과와 허용된 실행 환경이다. 검증이 기본 범위이며 발견한 결함의 수정 권한은 부모/사용자 지시를 따른다.

1. 사용자 행동·상태 전이·환경 의존 기준에는 [행동 시나리오](scenarios.md)를 읽고 원본 ID/이름·행동 순서·중간 상태·검증 환경을 이어받는다. 기준별 입력·정상/실패/복구 예상 결과와 실제 공개 경계를 정한다. CLI는 process의 exit/stdout/stderr, API는 요청·응답과 상태 전이, UI는 공개 제어의 조작 결과를 확인한다.
   외부 기능/옵션을 사용·변경하거나 환경 차이가 의심되면 [실행 환경 계약](runtime-contract.md)으로 실제 조합·실효 설정·최종 효과를 함께 확인한다.
2. UI 기준이 있을 때만 [UI 검증](verify/ui.md)을 읽는다. 도구와 provider가 실제 사용 가능한지 확인하고 정책 거절을 우회하지 않는다. 성능 수치를 판정할 때는 [측정 기준](optimize/measurement.md)을 읽는다.
3. 같은 변경의 인접 기존 동작과 실패 후 데이터 보존을 확인한다. 저장 상태·비동기·재시도·경합이 관련되면 [상태 검증](verify/stateful.md), 관찰에 설명되지 않는 동작이나 추가 실패 위험이 있으면 [추가 실험](verify/exploration.md)을 읽는다. 정적 분석·mock·screenshot만으로 실행하지 않은 경계를 PASS로 판정하지 않는다. 실행 가능한 검증을 사용자 검수로 넘기지 않는다.
4. [완료 증거](verify/evidence.md)로 기준별 PASS/FAIL/NOTRUN과 환경·근거를 반환한다. 필수 FAIL/NOTRUN이 있으면 전체 완료가 아니다. 인증·결제·데이터 변경의 독립 검토 결과는 실행자의 자기 검증과 별도이며 이 절차로 대체하지 않는다.
