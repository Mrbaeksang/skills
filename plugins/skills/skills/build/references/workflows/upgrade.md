# Upgrade

의존성의 목표 버전과 호환 조건을 판단하고 요청된 업그레이드를 코드 이행까지 수행한다. 최신 버전 확인만 필요하면 research를 사용한다.

1. [업그레이드 절차](upgrade/procedure.md)로 현재 해결 버전·runtime/peer·실제 사용 API·변경 위치·검증 기준을 정한다. 공식 근거가 부족할 때만 [research](research.md)를 사용한다.
2. 진단-only면 실행 가능한 변경 항목으로 반환한다. 실행 요청이면 호환 묶음 단위로 manifest·lockfile·소비 코드·설정을 변경한다. 불필요한 전체 패키지 업데이트나 새로운 bot 도입을 포함하지 않는다.
3. 변경된 계약의 [test](test.md)와 실제 경계의 [verify](verify.md)를 수행한다. 계획된 동일 검증을 반복하지 않는다. 설치/compile 통과만으로 완료를 선언하지 않는다.

결과는 목표 버전·선택 이유·실제 코드 이행·검증·남은 제약이다. 보안·권한·데이터 영향은 부모의 독립 검토 조건을 그대로 따른다.
