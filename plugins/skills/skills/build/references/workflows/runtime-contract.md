# 실행 환경의 계약 확인

외부 API·SDK·framework의 기능/옵션을 새로 사용하거나 변경할 때, 코드와 실행 결과가 어긋날 때, 버전·배포 설정 차이 또는 자원 누적 신호가 있을 때 읽는다. 문구 수정·순수 도메인 계산에 전체 의존성 감사를 붙이지 않는다. 부모 작업의 읽기/수정 권한을 그대로 따른다.

1. **조합을 식별한다.** 코드가 사용하는 기능과 실제 호출 경로를 찾고 manifest의 허용 범위, lockfile의 해결 버전, 설치된 client/runtime, 실행 중 server/service 버전을 구분한다. image tag나 배포 선언을 실행 중 인스턴스의 증거로 대신하지 않는다. 해당 기능에 영향을 주는 환경별 override·feature flag·권한·설정 우선순위와 최종 적용값을 확인한다. 비밀값은 출력하지 않는다. 관찰하지 못한 배포 환경은 미확인으로 남긴다.
2. **지원 조건을 대조한다.** 확인한 버전에 해당하는 공식 문서·release notes·타입/소스와 사용 옵션의 이름·단위·위치·기본값·필요 capability를 대조한다. client가 인자를 받아도 server가 지원한다는 보장은 없다. unknown option 무시, fallback, no-op, 경고만 남기는 경로도 확인한다. 정보가 부족하면 [research](research.md)를 적용하며 최신 문법이나 기억을 현재 호환성의 증거로 쓰지 않는다.
3. **효과를 관찰한다.** 기능의 use case에 대해 `초기 상태 → 공개 호출 → 예상 상태/효과 → 실제 관찰`을 연결한다. 성공 응답·컴파일·mock 호출 인자만으로 판정하지 않는다. 만료·취소·정리·재시도 한도·권한 제한처럼 제한을 거는 기능은 적용됐다는 응답뿐 아니라 이후 남아서는 안 되는 상태/작업이 없는지도 본다. 해당 제한이 실패하면 무엇이 얼마나 쌓이거나 계속 실행되는지, 기존 상한·관측 수단이 있는지 조사한다. 운영 데이터를 임의 변경하거나 스트레스 부하를 걸지 않는다.
4. **경계를 나눠 검증한다.** 필요하면 지원되는 조합/옵션 또는 override가 없는 조건을 대조군으로 쓰고 한 번에 한 변수를 바꾼다. 시간은 통제 가능한 시계나 제한된 관찰 구간을 사용한다. mock·local simulator는 로직 증거이며 실제 server 호환성 증거와 분리한다. 실제 의존성이 없거나 접근 권한이 없으면 그 경계는 NOTRUN이고, 관찰한 계약 위반은 FAIL이다.
5. **원인과 재발 방지를 연결한다.** 권한이 있으면 현재 조합에서 지원되는 사용법·설정으로 최소 수정한다. 버전 이행은 부모의 upgrade 절차와 승인 범위를 따른다. 잘못된 옵션·실효 설정·조용한 실패를 원인으로 고정하고 원래 사용자 시나리오와 실제 효과를 최종 코드로 재검증한다. 필요한 경우 지원 capability 사전 확인·계약 테스트·기존 관측 지표를 보강하되 모든 연동에 새 health check·호환 계층을 만들지 않는다. 코드 변경 없이 리뷰 중이면 근거와 수정 방향만 반환한다.

결과는 기존 보고에 `사용 기능 / 확인한 실행 조합·실효 설정 / 지원 근거 / 관찰한 효과 / 미확인 경계`를 필요한 만큼 포함한다. 별도 호환성 보고서 파일을 만들지 않는다. 자동 업그레이드나 버전 숫자만 바꾸는 것으로 해결했다고 주장하지 않는다.
