# 이미지 소비와 제작

콘텐츠 이미지의 제작·교체·확대를 요청받았거나 이미지가 선택·이해를 돕는 표현으로 필요할 때 읽는다. 문구만 수정하는 작업이나 이미지 변경이 없는 UI에 제작 절차를 붙이지 않는다.

실제 제품/성과를 입증하는 화면, 설명용 시각화, 아직 확보하지 못한 소재를 구분한다. 실제 근거는 확인한 원본을 사용하며 생성 이미지·모의 UI를 실사용 화면이나 고객 증거로 바꾸어 표시하지 않는다. 외부 자산은 출처·사용 권한을 확인한다.

1. **소비부터 결정.** 요청 범위의 콘텐츠 종류와 실제 화면/slot을 찾아 그림이 구별할 의미를 정한다. 기존 자산 재사용·제작·이미지 불필요와 이유를 같은 작업 원본에 연결한다. 이미 확인한 지도는 재사용하고, 파일 생성 개수를 적용 완료로 세지 않는다.
2. **표현 선택.** 정적 그림, transform 가능한 레이어, 프레임/sprite 중 실제 상호작용과 비용에 맞게 고른다. 본문 모든 문단에 그림을 붙이거나 모든 자산을 loop로 만들지 않는다. 선택·조언·결과를 가리지 않으며 텍스트와 접근성 의미를 보존한다.
3. **제작과 연결.** 필요한 경우 현재 제공된 이미지 전문 도구·스킬을 사용한다. 원본·제작 출처와 소비 key를 연결하고, 배경/투명 경계·표시 크기·종횡비·좁은 화면·실패 fallback을 확인한다. 제작 도구가 없으면 사용 가능한 자산과 미제작 범위를 구분하며 빈 연결을 완성처럼 보이지 않게 한다.
4. **비용과 수용.** 실제 표시 해상도·요청 수·전송/디코드·동시 재생과 배포 한도에 맞춰 형식·압축·지연 로딩을 선택한다. 특정 형식·atlas·라이브러리를 모든 제품의 필수로 만들지 않는다. 필요하면 기존 [프론트 측정](../optimize/frontend.md)을 적용한다. 실제 소비 화면에서 로드·실패·조작·reduced motion과 화면 밖 정리를 관련 범위로 확인한다. 생성 파일·정적 검사·렌더·실제 연동의 수락을 구분한다.
