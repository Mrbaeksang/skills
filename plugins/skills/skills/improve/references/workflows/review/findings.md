# 수정 후보 판정

개선·리뷰에서 수정 후보를 채택하기 전에 적용한다. 조사 전체를 반복하지 않고 후보의 결정적 주장만 확인한다.

1. `현재 지원 계약 → 실제 소비 경로 → 관찰된 위반 또는 비용`을 연결한다. 재현이 있으면 그 입력·환경과 결과를 재사용한다. 실행하지 않은 판단은 소스 근거로 표시한다.
2. 기존 guard와 의도된 경계가 후보를 반증하는지 확인한다. export·public·호출 가능성은 언어의 접근 범위이며 제품이 지원하는 소비 계약의 증거는 아니다. 가상 소비자를 상정한 중복 방어나 접근 제한은 실제 계약 위반·관찰된 비용이 없으면 정상 유지로 분류한다.
3. 결과를 **확정 문제 / 구분 실험 / 정상 유지 / 비용상 보류**로 판정한다. 수정 목록에는 확정 문제만 넣고, 실험에는 판정을 바꿀 관찰을 적는다. 정상 유지로 제외한 같은 후보를 표현만 바꿔 선택적 개선으로 다시 제안하지 않는다.
4. 확정 문제에는 보존할 동작과 검증 경계를 연결한다. 문서의 규칙이면 해당 조항, 성능 문제면 실제 workload·측정, 코드 결함이면 지원 경로의 기대/실제 차이가 근거다. 근거가 없는 일반 관례는 결함이 아니다.
