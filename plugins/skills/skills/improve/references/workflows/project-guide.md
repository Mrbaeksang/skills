# 프로젝트 지침 관리

프로젝트에서 반복해서 필요한 위치·명령·제약의 원본을 정비할 때 사용한다. 먼저 질문·검토인지 파일 생성·갱신인지 구분한다. 설명만 요청했으면 확인한 실행 방법과 근거를 채팅으로 반환한다.

1. 현재 작업 디렉터리와 프로젝트 루트, 적용되는 상위·하위 지침을 확인한다. 관련 README·스크립트·CI·설정과 실제 진입점을 대조한다. 모노레포에서는 명령의 실행 위치와 적용 패키지를 구분한다. 코드로 확인되는 사실은 재질문하지 않는다.
2. 기존 팀 정책·호스트 전용 내용·사용자 변경을 보존한다. 깨진 명령은 선언과 실행 경로를 확인하고 안전하게 가능한 범위에서 실행한다. 배포·외부 쓰기 같은 명령은 존재 확인과 실제 실행을 구분한다. 정책끼리 충돌하면 자동으로 덮어쓰지 말고 결정이 필요한 부분만 묻는다.
3. 쓰기 요청이면 기존 정본을 우선한다. 없으면 루트 AGENTS.md에 이 프로젝트에서 틀리기 쉬운 실행 위치·검증 방법·제약과 필요한 정본 링크만 둔다. 하위 규칙은 적용 범위를 유지한다. 빈 프로젝트에는 확인한 사실만 적고 계획·아키텍처·빈 docs 트리를 미리 만들지 않는다.
4. 여러 호스트를 요청하면 프로젝트 공통 정책은 한 곳에서 관리한다. 기존 CLAUDE.md의 공통 정책을 옮기면 원래 자리에 @AGENTS.md import를 두고 전용 정책은 유지한다. 기존 import·symlink와 순환 여부를 점검해 중복 참조를 피한다. 사용 중인 호스트의 실제 지원을 확인하며 전역 설정은 변경하지 않는다.
5. 최종 diff로 정책 소실·이중 원본·무관한 변경이 없는지 확인한다. 같은 요청을 다시 적용해도 추가할 내용이 없어야 한다. 근거 파일, 실행한 명령과 결과, 호스트 로딩 등 확인하지 못한 범위를 보고한다.
