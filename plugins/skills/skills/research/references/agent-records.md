# 에이전트 작업 기록

작업을 재개하거나 세션을 넘길 때, 중요한 결정을 보존할 때, 명세·티켓의 저장 위치를 정할 때만 읽는다. 답변을 파일로 바꾸는 절차가 아니다.

## 저장할지, 어디에 저장할지

- 한 번의 답변으로 끝나는 질문·분석·작은 수정은 채팅으로 끝낸다. 저장 요청이 없으면 REPORT.md, 분석 MD, HTML 보고서, 완료 영수증 파일을 만들지 않는다. 필요한 실제 테스트·로그·스크린샷은 검증 증거이며 별도 설명 보고서를 붙일 필요는 없다.
- 사용자 지정 위치와 기존 프로젝트의 issue·ADR·작업 기록을 먼저 사용한다. 같은 결정의 원본은 하나다. 기존 GitHub issue가 원본이면 로컬에는 필요한 링크·재개 상태만 둔다. 외부 게시 권한 없이 이슈를 생성하거나 수정하지 않는다.
- 기존 방식이 없고 다음 실행에 잃으면 안 되는 정보가 있으면 `.scratch/<task>/state.md` 하나로 시작한다. 파일 쓰기가 허용된 작업에서만 만들고, read-only/채팅-only 지시는 숨김 파일에도 적용한다. 매 호출마다 새 폴더·날짜별 보고서를 만들지 않는다.
- 독립적으로 참조·수정할 만큼 커진 명세나 티켓만 같은 작업 폴더의 `spec.md`, `issues/<id>.md`로 분리한다. 처음부터 빈 구조나 모든 파일을 만들지 않는다. 명세를 요청했을 때는 저장을 줄이려다 요구·실패 흐름·수용 기준을 생략하지 않는다.
- README·사용 설명·API 문서처럼 독자와 용도가 명확하거나 사용자가 요청한 산출물은 작성한다. 제품의 HTML·MD 콘텐츠도 이 금지 대상이 아니다. 기존 문서는 일괄 삭제·이동하지 않는다.

## 이어갈 수 있는 최소 내용

state에는 목표·허용 범위와 금지 사항·현재 상태·확정 결정과 근거·미결정·다음 행동, 관련 코드/이슈/검증 링크를 남긴다. 미완료 요구/수용 기준은 원본 ID·링크와 PASS/FAIL/NOTRUN·남은 행동을 연결해 보존한다. 다음 행동 한 줄로 나머지 요구를 대체하지 않는다. 진행 중인 전문 절차가 있으면 부모 작업에 필요한 결과와 확보한 근거/미완료만 기록한다. 호출 이력 전체는 필요 없다. 변경 작업이면 base/head와 소유 worktree도 적는다. 대화 전문, 내부 사고 과정, 명령 출력 전체, 비밀값은 복사하지 않는다. 추정·제안과 사용자 확정은 구분한다.

재개 시 사용자 제공 경로 → 프로젝트 지침/기존 tracker가 가리키는 작업 기록 → 현재 프로젝트 `.scratch/`의 작업별 진입 파일 목록 순서로 찾는다. 작업명·목표·소유 worktree가 현재 요청과 맞는 후보만 읽고, 여러 후보가 실제로 구별되지 않으면 짧게 질문한다. 후보가 없으면 기록이 없다고 밝히고 현재 파일에서 확인 가능한 범위만 이어간다. 기억을 지어내거나 관련 없는 작업 폴더·전체 결정 이력을 재귀적으로 읽지 않는다.

진입 기록의 현재 원본을 읽고 실제 코드·branch/head·issue 상태로 유효성을 확인한다. head가 다르면 관련 diff를 확인해 영향받은 근거만 다시 검증한다. 오래된 메모가 현재 파일이나 지시를 덮어쓰지 않는다. 미완료 요구·대기 질문·검증 경계와 새 제약을 복원한 뒤 현재 스킬의 조건부 참조를 다시 선택한다. 기록에 적힌 절차를 무조건 재실행하거나 이전 PASS를 다른 환경에 이월하지 않는다. 권한이 줄면 새 범위를 따른다.

여러 작업이 의존하거나 나중에 이유를 잃기 쉬운 중요한 결정만 안정적인 ID와 짧은 문단으로 분리한다. 기존 결정 저장소가 없으면 `.scratch/decisions/<stable-id>.md`를 쓸 수 있다. 단순 구현 선택마다 ADR을 만들지 않는다.

결정에는 `상태 / 결정과 이유 / 근거 / 영향받는 작업`을 남기고, 바뀌면 새 결정에서 이전 결정을 `supersedes`로 연결한다. 기존 기록은 이유와 `superseded-by` 링크를 남겨 보존한다. 외부 원본 수정 권한이 없으면 역링크 갱신을 주장하지 않는다. 현재 진입 기록은 최신 결정을 직접 가리킨다. `depends-on`은 실제 선행 조건에만 쓰고 단순 관련 링크와 구별한다. 순환하는 선행 관계·끊어진 링크·대체된 결정을 현재 결정으로 쓰는 오류를 점검한다.

예: `issue #42 → D-viewer-native → 근거: 기존 viewer 호출부·정책 → 구현 PR → 검증`. 독자가 코드를 찾아갈 수 있는 파일 경로/심볼이나 issue URL을 쓰고 로컬 scratch 경로만 외부 이슈에 붙여 다른 사람이 읽을 수 있다고 가정하지 않는다.

## 저장 수명과 인계

- 작업 중에는 의미 있는 결정·차단·인계 시 같은 기록을 갱신한다. 현재 상태·요구별 판정·head·다음 행동은 제자리에서 최신화하고, 새 결과를 끝에 덧붙인 채 앞의 과거 PASS나 다음 행동을 현재처럼 남기지 않는다. 보존할 이전 근거는 적용 revision과 함께 과거 이력으로 구분한다. 종료 시 원본의 미완료 요구가 모두 결과 또는 남은 행동에 연결됐는지 대조하고, 사용자에게는 결과와 진입 경로만 보고한다. abrupt 종료 전에 저장되지 않은 대화나 접근 불가능한 기록은 다음 세션에 전달됐다고 보장하지 않는다.
- 숨김 폴더는 보안 경계도 영속 저장 보장도 아니다. 임시 메모와 실행 부산물은 기본적으로 commit하지 않는다. 기존 ignore 규칙을 존중하고 필요하면 해당 임시 경로만 로컬 exclude에 추가한다. `.scratch/` 전체를 무조건 ignore하지 않는다.
- 다른 세션·worktree·협업자에게 필요한 결정은 접근 가능한 기존 issue/ADR 또는 버전 관리되는 결정 파일에 남긴다. 공유할 가치와 권한이 있을 때만 승격하고 임시 기록은 원본 링크로 바꾼다. 자동 공개·이중 원본·새 동기화 시스템은 만들지 않는다.
- worktree를 지우기 전에 필요한 기록이 접근 가능한 원본에 인계됐는지 확인한다. 소유한 임시 기록만 정리하며 무관한 파일과 근거 없는 오래된 기록 삭제는 하지 않는다.
