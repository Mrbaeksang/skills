# Research

입력은 답할 질문, 결정을 바꿀 사실, 기존 stack·제약과 필요한 결과다. 기본 출력은 채팅이며 조사 MD를 자동 생성하지 않는다.

1. 로컬 manifest·lockfile·설정·기존 결정으로 이미 아는 것을 먼저 확인한다. 최신 사실이나 외부 근거가 필요하면 원문을 소유한 공식 문서·release notes·source를 확인한다.
2. 도구 호출 성공과 조회 성공을 구분한다. HTTP·인증 오류, HTML 오류 페이지, 파싱 실패는 근거가 아니다. 빈 결과는 조회 범위·필터·권한을 확인하기 전까지 부재의 증거로 단정하지 않는다. 설정된 MCP도 실제 도구가 노출되지 않으면 사용 가능하다고 가정하지 않는다. 실패 시 사용 가능한 공식 도구·원문으로 대체하고 같은 실패를 무한 반복하지 않는다. 검색 요약과 기억은 조회한 사실과 구분하고 URL·확인일·대상 버전·미확인 항목을 남긴다. 특정 vendor의 설치·인증을 모든 조사에 강제하지 않는다.
3. 기술 선택지 비교일 때만 [기술 비교](research/technology.md)를 읽는다. 단일 API 사실 조회에 후보표·전수 조사를 만들지 않는다. 버전 변경 실행은 이 절차의 범위가 아니다.
4. 의사결정을 가르는 근거가 모이면 중단한다. 답·추천과 바뀌는 조건·제약·미확인을 부모에 돌려주며 사용자의 제품 결정을 몰래 확정하지 않는다.
