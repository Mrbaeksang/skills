# 증거의 대표성

성공 사례 하나는 검증이 아니다. 실제 사용에서 달라지는 조건을 골라 그 조건들에서 결과를 확인한다.

## 신호

- 검증을 끝내고 완료로 판정하려 한다.
- 화면·응답에 목록이 있거나, 개수·상태·입력 길이·권한·글자 크기·화면 너비가 달라질 수 있다.
- 확인한 근거가 캡처 한 장, 요청 하나, 질문 몇 개뿐이다.
- 외부 모델·외부 서비스처럼 결과가 매번 다를 수 있는 것을 쓴다.

## 확인할 질문

1. 사용자가 실제로 만나는 조건 중 결과가 달라질 수 있는 축은 무엇인가: 0개·1개·여러 개, 정상·빈·오류·로딩, 짧은 입력·긴 입력, 권한 있음·없음, 작은 화면·큰 글씨.
2. 서로 간섭할 수 있는 것이 함께 있을 때를 확인했는가: 같은 부품 여러 개, 동시 요청, 이전 상태가 남은 재방문.
3. 결과가 확률적이면 몇 번, 어떤 입력 종류로 재 봐야 판단할 수 있는가.

## 수행

- 축마다 대표값을 하나 이상 골라 실행한다. 모든 조합을 돌리지 않고 결과를 바꿀 수 있는 조합을 고른다.
- 확률적인 결과는 입력 종류별로 묶어 세고, 실패는 원인과 함께 기록한다.
- 시각 결과는 여러 상태의 캡처를 같은 조건으로 비교한다.

## 보고

- 확인한 조건과 확인하지 않은 조건을 나눠 말한다. 하나의 성공으로 전체 PASS를 주장하지 않는다.

## 예

- UI: 카드 한 장일 때만 확인 → 카드 여러 장이 함께 뜨는 기록 화면에서 사라지는 결함을 놓친다.
- AI 응답 형식: 질문 4개로 판단 → 감정 토로·잡담·위험 질문 같은 다른 유형에서 형식이 어긋난다.
