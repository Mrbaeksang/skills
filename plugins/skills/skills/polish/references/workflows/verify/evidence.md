# 완료 증거

입력의 수용 기준마다 다음 정보를 남긴다. 작은 변경은 한 줄로 합쳐도 된다.

| 요구 ID | use case / 실행 입력 | 예상 관찰 | 실제 관찰 및 증거 위치 | 판정 |
|---|---|---|---|---|
| 원본 ID | actor, 조건, 공개 호출 | 외부 결과·불변식 | 명령/도구, exit/status, 출력 또는 조작 결과 | PASS / FAIL / NOTRUN |

함께 기록할 것:

- 실제 환경·도구 버전, 검사한 branch/worktree와 변경 범위. 비밀정보는 기록하지 않는다.
- 의미 있는 실패의 원인과 수정 후 같은 경계의 결과. 테스트를 생략했다면 위험과 직접 검증 근거.
- 변경 전후 무관한 tracked/untracked 작업 보존 여부.
- 오류의 도메인 소유권과 외부 변환 계약, 해당하는 권한·경계·복구 결과.
- 실행하지 않은 플랫폼/도구/시나리오, 이유와 재개에 필요한 구체적 조건.
- 현재 상태와 전환 근거. NOTRUN인 필수 runtime 항목이 있으면 완료가 아니다. 외부 의존/권한으로 멈춘 경우에만 blocked 원인과 재개 조건을 기록하며 검증 중인 작업은 active로 둔다.

CLI 호출 한 번의 성공을 API·UI 또는 다른 플랫폼의 성공으로 확대하지 않는다. 독립 검토는 구현자의 자기 점검과 구분한다.
