# 상호작용의 표현

조작 피드백·상태 전환·모션·표면과 아이콘의 완성도를 설계하거나 수정할 때 적용한다.

- 조작 가능성, 현재 상태, 처리 결과가 일관되게 보이게 한다. 버튼의 accessible name, focus, 키보드/포인터 경로와 비활성·진행·실패 상태의 의미를 먼저 확인한다. 장식이 깨진 조작보다 우선하지 않는다.
- 사용 빈도와 목적에 맞춰 피드백 강도를 정한다. 반복 행동은 지연 없이 반응하게 하고, 모션은 변화의 원인·방향·완료를 이해하는 데 쓰인다. 프로젝트의 기존 시간·곡선 토큰을 출발점으로 실제 속도에서 조절한다.
- 진행 중 다시 조작하거나 취소할 때 최신 의도에 맞게 전환되는지 확인한다. 모션을 줄이거나 끈 상태에서도 결과와 의미가 남아야 한다. 애니메이션 완료를 기능 완료의 선행 조건으로 만들지 않는다.
- 그림자·테두리·중첩된 곡면은 깊이·그룹·경계를 구분하는 역할로 고른다. 수학적 중앙과 실제 시각적 무게가 다르면 실제 글꼴·아이콘·배경에서 광학적 균형을 조절한다. 모든 버튼에 같은 효과·보정값을 기계적으로 적용하지 않는다.
- 같은 아이콘/행동의 의미와 상태 표현을 일관되게 유지하고, 실제 [행동 시나리오](../scenarios.md)의 전·중·후를 확인한다. 보기 좋은 정지 화면이 사용 중 전환을 입증하지 않는다.
