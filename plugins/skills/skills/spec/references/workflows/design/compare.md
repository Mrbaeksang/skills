# 시각 대안 비교

중요한 시각 선택이 미정이고 직접 비교가 판단에 도움이 될 때만 사용한다. 확정된 디자인의 구현이나 작은 수정에는 생략한다.

1. 결정할 질문과 바꿀 축을 하나 정한다. 구조·밀도·위계 같은 선택이 사용자 과제에 어떤 차이를 만드는지 설명 가능한 2–3개 방향을 잡는다. 색만 바꾼 시안이나 모든 축을 동시에 바꾼 후보는 피한다.
2. 구현이 허용되면 실제 페이지 맥락·기존 컴포넌트·현실적인 콘텐츠로 비교한다. 프로젝트에 있는 preview/Storybook/fixture를 우선하고 없을 때만 작업 범위 안에 임시 미리보기를 만든다. 읽기-only이면 방향과 trade-off만 제시한다.
3. 같은 콘텐츠·크기·상태에서 한 번에 한 후보를 실제 크기로 보고 조작한다. 모든 후보가 같은 접근성·기능 기준을 충족해야 한다. 작은 썸네일이나 mock 화면으로 실제 연동 성공을 주장하지 않는다.
4. 어떤 조건에서 유리하고 무엇을 희생하는지와 추천 이유를 짧게 전달한다. 사용자 판단이 필요한 차이만 묻고 이미 위임된 선택은 진행한다. 렌더링하지 못했으면 선택의 시각 근거는 미검증으로 남긴다.
5. 선택 후 제품 경로에 반영하고 이번 작업이 만든 임시 후보·진입점만 정리한다. 사용자가 계속 비교하기를 원하면 유지한다. 분석 보고용 HTML을 자동 생성하거나 기존 사용자의 fixture를 삭제하지 않는다.
