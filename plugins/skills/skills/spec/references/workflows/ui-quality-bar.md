# UI 품질 기준

새 화면, 새 사용자 흐름, 구조·시각 재설계를 만들거나 그 명세·결과를 검토할 때 이 기준을 먼저 적용한다. 문구만 바꾸는 수정, 기존 디자인 시스템 안의 국소 수정, 기능·성능만 바꾸는 수정에는 적용하지 않는다. 사용자가 명시한 브랜드·디자인 시스템과 접근성 요구는 이 기준보다 우선한다.

## 1. 운영 중인 서비스와 나란히 놓아 판정한다

- **비교 기준.** 사용자가 지정한 서비스나 화면이 있으면 그것을 쓴다. 없으면 같은 범주에서 실제로 운영 중인 서비스 2~3개를 고르고, 이름과 고른 이유를 사용자에게 알린다. 직접 관찰한 화면과 공개 자료(스토어 이미지, 공식 스크린샷)를 구분하고 출처를 남긴다. 보지 못한 화면을 본 것처럼 쓰지 않는다.
- **판정 방법.** 같은 콘텐츠·같은 화면 크기·같은 상태에서 결과 스크린샷을 기준 화면과 나란히 놓는다. 작성 맥락이 없는 검토자(새 세션 또는 subagent)가 다음 항목에서 기준보다 뒤지는 점을 목록으로 만든다.
  - 서체 위계: 크기와 굵기의 대비
  - 간격 리듬, 정렬, 색의 역할
  - 콘텐츠와 이미지의 우선순위
  - 정보 밀도, 터치 영역, 상태 전환
- **완료 조건.** 뒤지는 항목이 남아 있으면 시각 목표는 미완료다. 고칠 대상이지 NOTRUN이 아니다. 실행자의 자기 평가, 자동 검사 통과, overflow 없음은 이 판정을 대신하지 않는다. 렌더링할 수 없으면 시각 판정은 NOTRUN이다.

## 2. 생성 기본값을 쓰지 않는다

아래 기본값은 제품 근거(브랜드 가이드나 사용자 지정)가 있을 때만 쓴다. 근거 없이 쓰였으면 결함이다.

- 기본 시스템 서체 하나로 크기만 바꾼 위계
- 제품과 무관한 보라·파랑 그라디언트
- 모든 구획을 같은 둥근 카드와 그림자로 감싸는 배치
- 장식용 시머, 반복 모션, 진입마다 흩어진 애니메이션
- 실제 데이터가 아닌 배지·이모지·숫자 강조
- 무엇을 할 수 있는지 말하지 않는 추상적 헤드라인

하나를 피한 뒤 또 다른 흔한 기본값으로 바꾸는 것도 같은 결함이다. 서체·색·밀도·모션의 방향을 한 문장으로 정하고 화면 전체에 일관되게 적용한다.

## 3. 층을 더하지 않는다

화면·모달·시트·메뉴 항목·접기/펼치기·안내 패널·별도 상태 문구는 모두 층이다. 층을 하나 더하려면 **제자리에서는 할 수 없는 사용자 판단**을 근거로 적어야 한다. 근거를 적지 못하면 만들지 않는다.

다음은 근거 없이 만들어지기 쉬운 층이다. 기본적으로 만들지 않는다.

- 주 콘텐츠 위의 힌트·추천 패널과 그 접기·펼치기
- 화면에 이미 보이는 정보를 다시 띄우는 상세 팝업
- 내용이 준비되지 않았을 때 띄우는 빈 대기 모달
- 내부 상태(기억, 로그, 동기화 상태)를 사용자 기능으로 노출한 메뉴·시트
- 두 화면 사이의 중간 로딩 화면
- 제자리 표시와 겹치는 별도 상태 문구
- 한 번의 선택을 위해 여러 단계로 들어가는 설정

예외는 되돌릴 수 없는 결과(삭제, 결제, 외부 공개)의 확인과, 법적 동의·권한 요청뿐이다.

명세의 상태(비어 있음, 불러오는 중, 실패, 재시도)는 같은 자리에서 표현하는 것이 기본이다. 새 표면이 필요하면 근거를 적는다. 결과 보고에는 진입부터 핵심 행동까지의 탭 수와 추가한 층, 각 층의 근거를 남긴다. 기준 서비스가 있으면 탭 수와 층 수를 비교한다.

## 4. 새 화면·흐름은 시안을 고른 뒤 구현한다

- 새 화면, 새 흐름, 기존 흐름의 구조를 바꾸는 작업은 제품 경로를 수정하기 전에 시안 2~3개를 보여 주고 사용자에게 선택을 받는다. 시안은 실제 콘텐츠로 렌더한 화면이나 스크린샷이다. 시안끼리는 구조·밀도·위계 중 한 축만 다르게 하며, 색만 다른 시안은 시안이 아니다. 각 시안에 2절과 3절의 기준을 적용한다.
- 사용자가 결정을 명시적으로 맡겼으면("알아서 정해") 시안 대기 없이 진행한다. 고른 방향과 근거는 보고한다.
- 경쟁 서비스에서 관찰한 기능은 요구사항이 아니라 후보로 기록한다. 사용자가 고르거나 명세가 확정한 것만 구현한다.
- 고른 결정은 명세나 기존 작업 기록에 남긴다. 그 결정을 뒤집는 변경만 다시 묻는다. 작은 수정, 기존 방향 안의 변경, 문구 치환은 시안 단계 없이 진행한다.

## 5. 보고

짧게 정리한다. AS-IS 문제 → 고른 방향과 근거 → 비교 결과(뒤지는 항목과 처리) → 추가한 층과 근거, 탭 수 → 실제 검증과 NOTRUN.
