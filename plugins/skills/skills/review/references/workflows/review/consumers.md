# 변경 계약의 소비자 추적

enum·허용 입력·공개 응답·상태 전이·공유 설정 계약이 바뀔 때 읽는다. 전체 레포 전수 리뷰가 아니라 변경 값과 경계를 사용하는 경로를 추적한다.

1. 변경된 생산자와 이전/새 계약을 고정한다. 참조·기존 sibling 값·등록 경로를 검색해 소비자 후보를 찾는다.
2. 후보의 실제 코드를 읽고 검증 → 저장 → 변환 → 분기 → 표시의 관련 경로를 확인한다. 검색 결과만으로 지원 여부를 판단하지 않는다. allowlist, switch/default, 직렬화·역직렬화, config override의 누락을 살핀다.
3. 영향을 받는 입력과 도달 경로, 예상/실제 동작을 연결한다. fallback이 새 값을 의도대로 처리하면 결함이 아니다. diff 밖 기존 코드도 새 계약 때문에 깨진다면 변경의 영향에 포함한다.
4. 영향받는 공개 경계의 기존 증거를 확인하거나 허용된 최소 재현을 수행한다. 미탐색 소비자·실행하지 않은 경계를 남긴다. 리뷰-only는 finding으로 반환하고 자동 수정하지 않는다.
