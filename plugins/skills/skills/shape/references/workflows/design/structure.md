# 구조와 밀도

레이아웃·읽기 순서·반응형 구조를 결정하거나 바꿀 때 적용한다.

- 사용자의 판단에 필요한 정보와 주요 행동을 먼저 배치하고 보조 정보는 같은 기준으로 정렬한다. 수치 비교·탐색·읽기 중 과제에 맞는 구조를 택한다. 카드가 필요한지보다 정보 사이의 관계가 무엇인지 먼저 정한다.
- 같은 묶음 내부 간격과 묶음 사이 간격을 구분한다. 기존 spacing 단계를 사용하고 불필요한 구획선을 추가하기 전에 여백과 정렬로 관계를 표현할 수 있는지 확인한다.
- 좁아질 때 우선순위·읽기 순서·조작 가능성을 유지하도록 재배치한다. 단순 축소나 모든 열 숨기기로 사용자가 해야 할 비교를 잃지 않게 한다. 숨기거나 잘라낸 정보는 필요한 경우 도달 경로가 있어야 한다.
- 실제 콘텐츠의 길이·개수·지역화·권한별 차이를 코드와 요구에서 도출한다. [행동 시나리오](../scenarios.md) 중 해당 상태로 같은 컴포넌트를 확인한다. 고정 높이·폭이 다양한 내용을 수용하는지 보며 제품에서 불가능한 조합은 만들지 않는다.
- 시각 순서와 탐색 순서가 어긋나지 않는지, 상태가 바뀌어도 사용자의 현재 위치와 맥락을 유지하는지 실제 화면에서 확인한다. 화면 밖 정보를 발견할 단서와 조작 영역을 콘텐츠와 구분한다.
