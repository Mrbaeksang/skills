# 레퍼런스를 설계로 옮기기

사용자가 참고 화면·사이트·이미지를 지정했거나, 새 화면·재설계의 비교 기준 서비스를 정할 때 읽는다. 이미 정해진 브랜드의 국소 수정에는 레퍼런스 수집을 추가하지 않는다. 관찰한 기능은 요구사항이 아니라 후보로 기록한다.

1. **관찰 범위.** 접근 가능한 원본의 실제 화면과 관련 상태를 확인한다. 스크린샷만 있으면 보이는 구도·위계만 근거로 삼고 조작·반응형 동작을 추정해 확정하지 않는다. 접근 불가한 자료를 본 것처럼 설명하지 않는다.
2. **원리 추출.** 무엇을 먼저 읽게 하는지, 정보의 밀도·그룹·선택/변화 표현이 사용자 과제에 어떻게 도움이 되는지 고른다. 색상이나 스타일 이름만 나열하지 않는다. 서로 다른 자료에서 무관한 장식을 모으거나 사이트 전체를 복제하지 않는다.
3. **현재 제품에 대응.** 참고할 원리 → 우리 콘텐츠·행동 → 유지/변경할 구현을 짧게 연결한다. 기존 토큰·컴포넌트·브랜드를 확인하고, 레퍼런스의 짧은 영문·적은 데이터가 긴 한국어·다수 항목에서도 성립하는지 판단한다. 과제가 다르면 원리도 채택하지 않는다.
4. **소재와 사실.** 실제 제품 화면·고객 근거, 설명용 이미지, 아직 없는 자료를 구분한다. 없는 로고·후기·성과를 채워 넣지 않는다. 자산을 가져올 때 출처와 사용 권한을 확인하고 생성 이미지를 실제 제품·고객 증거로 표현하지 않는다. 자료가 부족하면 현재 사실만으로 구성을 완성하거나 부족한 부분을 명확히 남긴다.
5. **대조.** 구현했다면 실제 콘텐츠·지원 크기·중요 상태에서 선택한 원리가 유지되는지 원본과 나란히 비교한다. 픽셀 복제가 아니라 사용자 판단/행동을 돕는지 확인한다. 실제 화면을 실행하지 못했으면 설계 제안과 검증 결과를 구분한다. 선택과 이유는 기존 작업에만 연결하고 별도 무드보드·보고서를 자동 생성하지 않는다.
