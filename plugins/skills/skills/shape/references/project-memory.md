# 프로젝트 기억

프로젝트의 지속 결정·반복 함정을 찾는 짧은 진입점이다. [작업 기록](agent-records.md)의 원본·대체 관계·권한 규칙을 사용하며 별도 결정 저장소를 만들지 않는다.

## 찾고 읽기

- 프로젝트 지침이 지정한 기존 이슈·ADR·기억 진입점을 우선한다. 없으면 기존 작업 기록이 가리키는 원본을 사용한다. 저장소 전체나 전체 결정 이력을 탐색하지 않는다.
- 지정 위치가 없으면 `.scratch/project-memory.md`의 존재만 확인한다. 파일이 없고 보존할 정보도 없으면 생성하지 않는다.
- 진입점의 짧은 요약을 읽고 현재 작업의 결정에 필요한 원본만 따라간다. 현재 파일·사용자 지시·원본의 상태가 우선이며, 과거 PASS를 새 환경으로 이월하지 않는다.

## 남길 때

반복 지적, 사용자의 지속 결정, 재발할 함정·전달 경로 중 다음 작업에도 필요한 사실만 남긴다. 지적 횟수 자체가 영구 규칙의 근거는 아니다.

- 기존 결정 원본이 있으면 본문을 복제하지 않고 ID·짧은 요약·원본 링크만 남긴다. 기존 프로젝트 지침이 같은 역할을 하면 새 진입점도 만들지 않는다.
- 원본이 없으면 짧은 사실은 이 진입점에서 소유한다. 독립 변경이 필요한 결정만 작업 기록 규칙에 따라 분리하고 링크한다. 권한은 사용자 원문·대상·환경·행위·유효 조건을 포함하고 해석과 구분한다.
- 결정 변경은 원본에서 `supersedes` 관계로 이어지고 진입점은 최신 원본을 가리킨다. 외부 원본을 고칠 권한이 없으면 변경 필요를 보고하며 갱신했다고 주장하지 않는다.
- 파일 쓰기가 허용된 범위에서만 갱신한다. read-only에서는 제안만 한다. 파일 생성이 commit·공유·공개 허용을 뜻하지 않는다. 다른 세션·기기는 실제 접근 가능한 기록만 이어받는다.
- 진행 보고·대화 전문·비밀값·개인정보·코드로 바로 알 수 있는 사실은 넣지 않는다. 관련 없는 기록은 보존한다.

형식은 `ID / 요약 / 원본 링크(없으면 이 파일이 원본) / 적용 조건`이면 충분하다. 길어지면 중복 요약을 줄이고 상세 내용은 기존 원본에 둔다. 폐기·대체된 결정의 근거를 나이만으로 삭제하지 않는다.
