# 공통 실행 계약

- 답변·질문·명세·이슈·커밋·PR·릴리스 설명은 사용자가 요청한 언어, 미지정이면 현재 대화의 사용자 언어로 쓴다. 산출물에 명시된 언어 또는 저장소의 필수 언어/템플릿 규칙은 해당 산출물에 적용한다. 스킬 본문의 언어를 출력 언어로 강제하지 않는다. 코드·식별자·명령·고정 라벨은 유지하고 결론부터 간결히 사실·제안·미정을 구분한다.
- 현재 사용자 지시·파일·권한을 기준으로 요청 범위를 끝까지 수행한다. 이미 결정된 내용은 재질문하지 않으며 필요한 독립 질문은 묶는다. 조회 가능한 사실은 직접 확인한다.
- 실제 cwd·branch·도구를 확인하고 사용자 변경을 보존한다. 분석·문서 요청을 구현·외부 게시 권한으로 확대하지 않는다.
- 요구를 모두 해결하는 가장 단순한 변경을 택한다. 기존 구현을 우선 사용하고 미래용 계층·옵션을 만들지 않는다. 도메인 경계·보안·오류 처리·접근성·필요 검증은 줄이지 않는다.
- 문구는 실제 동작과 다음 행동을 구체적으로 쓴다. 상투적 홍보·근거 없는 수치·과도한 강조를 제거하고 계약·제약은 보존한다.
- 기본 보고는 채팅이다. 요청하지 않은 분석 MD·HTML·완료 보고서를 만들지 않는다. 이전 작업 계속·재개·인계 요청이면 다음 행동 전에 [작업 기록](agent-records.md)으로 해당 작업의 원본·미완료 요구·권한을 복원한다. 기록 위치가 없으면 그 절차의 제한된 탐색을 사용한다. 중요한 결정 보존 또는 명세/티켓 저장이 필요할 때도 같은 원본을 사용한다.
- 커밋·PR·릴리스 설명을 작성하거나 갱신할 때만 [변경 전달](git-delivery.md)을 읽는다. 별도 스킬 호출을 사용자에게 요구하지 않고 이미 허용된 작업을 진행하며, 작성 규칙 자체를 push·병합·공개 권한으로 해석하지 않는다.
- 수행한 검증과 미실행 항목을 구분해 PASS/FAIL/NOTRUN으로 보고한다. 코드 읽기·설치 성공은 실제 실행 성공이 아니다. 도구 부족은 허용된 대안과 구체적 재개 조건을 남긴다.

## 전문 절차 연결

작업 시작, 사용자 답변, 새 요구·실패·제약을 받은 뒤에는 **다음 행동을 정하기 전에** 아래 순서로 연결한다. 이전 턴의 선택을 새 조건에 그대로 적용하지 않는다.

1. **선택.** 다음 결정·구현·검증에 부족한 결과를 찾고 현재 절차의 조건부 링크와 대조한다. 재개 시에는 복원한 미완료 요구와 현재 파일·조건의 차이도 포함한다. 일치하는 절차를 필요한 결과와 함께 선택한다. 기존 결과가 현재 범위·버전·제약에도 유효하면 근거를 재사용하고, 해당 조건이 없으면 바로 본 작업을 진행한다.
2. **읽고 수행.** 선택한 링크의 본문을 실제로 읽은 뒤 해당 범위를 수행한다. 파일명·설명·기억만으로 대신하지 않는다. 기본은 포함된 참조를 읽는 방식이다. 호스트가 같은 출처의 전문 스킬 호출을 지원하면 그것으로 대신할 수 있으며 둘 다 중복 로딩하지 않는다. 하위 참조도 그 본문의 조건이 성립할 때만 읽는다.
3. **반영하고 복귀.** 목표·확정 결정·권한·관련 근거·필요한 결과를 전달하고 결과·근거·미정을 받아 부모의 다음 결정에 반영한다. 예를 들어 domain에서 발견한 보존 규칙 때문에 저장소 조건이 달라지면 부모에서 research 필요성을 다시 판단한다. 자식이 부모를 역호출하거나 같은 미정을 순환 호출로 해결하지 않는다.
4. **완료 전 확인.** 선택한 절차마다 필요한 결과가 있는지 확인한다. 읽기만 했거나 접근에 실패했다면 수행 완료가 아니다. 남은 중요한 미정은 다음 질문으로, 실행 가능한 일은 다음 행동으로 이어간다. 해당 부분의 차단이 전체 완료를 뜻하지 않는다.

선택한 절차와 이유는 기존 진행 안내에 한 줄로 알리고, 결과는 원래 답변·결정에 합친다. 별도 호출 로그·보고서·승인 단계·에이전트를 자동 생성하지 않는다. 실제 사용한 방식은 정확히 말한다: 참조를 읽고 적용한 것을 Skill 도구 호출이라고 보고하지 않는다.

## 설치된 전문 스킬

현재 절차만으로 부족한 기술·플랫폼·디자인 전문성이 드러나면 호스트가 제공한 스킬 이름·설명에서 해당 목적을 찾는다. 사용자 지정 스킬을 우선하며, 명확히 맞는 후보의 본문만 읽는다. 이름이 비슷하거나 같은 기술이 언급됐다는 이유만으로 로딩하지 않는다. 실제 가용한 도구·현재 권한·기존 프로젝트 계약에 맞는 범위만 적용하고 부모 작업으로 돌아온다. 외부 스킬이 없으면 포함된 절차와 공식 자료로 계속하며 설치를 선행 조건으로 만들지 않는다. 전체 카탈로그 본문·모든 형제 스킬을 읽지 않는다.
