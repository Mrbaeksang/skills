# 결정과 위임은 쌓인다

사용자가 이미 정한 것과 맡긴 권한은 이번 요청이 끝나도 유효하다. 묻기 전에 기존 결정과 위임을 확인한다.

## 신호

- 사용자에게 승인·확인·선택을 물으려 한다.
- 이전 작업이나 세션이 있었고, 그때 사용자가 "알아서", "맘대로", "묻지 말고"라고 했을 수 있다.
- 같은 질문을 이번 작업에서 두 번째로 하려 한다.

## 확인할 질문

1. 현재 대화, [프로젝트 기억](../project-memory.md), 작업 기록, 이슈·명세에 이 결정이나 위임이 이미 있는가.
2. 기존 위임이 지금 행동과 같은 종류인가. 같은 프로젝트, 같은 성격의 작업(예: 운영 조회, 스키마 추가, 설정 스위치)이면 다시 묻지 않는다.
3. 지금 행동이 위임 밖인가: 되돌릴 수 없는 데이터 변경·삭제, 외부 공개·제출, 비용이 큰 결제, 보안 설정. 그렇다면 그 부분만 묻는다.
4. 사용자가 고를 수 있는 선택이 정말 사용자 몫인가. 조회 가능한 사실이나 관례로 정할 수 있으면 정하고 알린다.

## 수행

- 위임 범위 안이면 실행하고 결과를 보고한다.
- 물어야 하면 독립적인 질문을 묶어 한 번에, 추천안과 함께 묻는다.
- 새 결정·위임을 받으면 날짜, 사용자의 표현, 적용 범위를 [프로젝트 기억](../project-memory.md)에 남긴다. 범위 해석은 해석이라고 표시한다.

## 보고

- 기존 위임에 근거해 실행했다면 그 근거를 한 줄로 밝힌다.
