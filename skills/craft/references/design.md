# 재사용할 행동 설계

## 실제 작업에서 추출

관찰한 요청·작업 순서·수정 피드백·산출물에서 반복되는 판단을 찾는다. 실패 사례는 `어떤 조건 → 어떤 판단/연결이 빠짐 → 어떤 사용자 결과가 깨짐`으로 설명한다. 특정 제품명·버전·한 번의 장애를 범용 필수 점검으로 바꾸지 않는다. 도구 오류나 확정적으로 검사 가능한 규칙은 실행 경로·검사기로 해결하고 문서에 우회법을 쌓지 않는다.

기존 스킬의 같은 책임을 먼저 찾는다. 자료를 조회할 수 있으면 직접 읽고, 접근 불가·권한·중대한 사용자 선택만 질문한다. 외부 방법론이나 최신 도구 사실이 필요한 경우에만 [research](workflows/research.md)를 읽고 현재 허용된 출처로 확인한다. 유명한 저장소의 지침이라는 이유만으로 효과가 입증됐다고 보지 않는다.

## 호출과 실행의 계약

- **호출:** 실제 능력과 언제 필요한지를 짧은 이름/description에 쓴다. 비슷한 인접 작업과 혼동되는 경계만 명시한다. 호출률을 올리려고 무관한 키워드를 늘리지 않는다.
- **입력과 권한:** 필요한 원자료·현재 상태·허용 효과를 식별한다. 정보가 없으면 무엇을 묻거나 확인할지, 사용할 수 없는 도구가 있으면 무엇까지 수행할지 정한다.
- **판단과 결과:** 원하는 행동을 실행 가능한 순서·관찰 가능한 결과로 쓴다. 규칙 준수 선언이나 고정된 문구 대신 실제 산출물·상태 변화로 완료를 판정한다. 보류·미검증·사용자 답변 대기를 완료와 구분한다.
- **분리:** 모든 요청에서 필요한 판단은 진입점, 특정 조건에서만 필요한 상세 절차는 참조로 둔다. 각 링크에는 읽을 조건과 부모에 돌려줄 결과를 붙인다. 핵심 판정이 깊은 참조에서 누락됐다면 먼저 필요한 결정 단계에서 직접 연결한다. 참조를 읽는다는 것만으로 별도 실행 컨텍스트가 생기지는 않는다.

짧은 스킬은 한 파일이면 충분하다. `SKILL.md`의 YAML front matter에 `name`과 `description`을 두고, `name`은 소문자·숫자·하이픈으로 된 설치 폴더명과 일치시킨다. 사용자가 경로를 지정했다면 그 마지막 폴더명을 기준으로 한다. 공통 의미는 기존 원본에 두고, 단독 설치에서도 참조가 해결되는지 확인한다. 설치 호스트의 호출 정책은 실제 지원 형식에 맞추고 자동 호출을 임의로 끄지 않는다. 외부 스킬의 설치를 숨은 선행 조건으로 만들지 않는다.

## 수정 범위를 고르기

실행 기록의 실패 위치를 구분한다: 선택되지 않음 → description/호스트 발견; 선택됐지만 필요한 자료를 안 읽음 → 참조 조건·위치; 읽었지만 잘못 적용 → 판단/출력 계약; 올바른 절차지만 도구 실패 → 실행 환경; 잘못된 과제가 통과 → 평가 기준. 원인에 맞는 부분만 바꾼다. 같은 문장을 다른 곳에 반복해 중요도를 높이거나 모든 상황에 더 강한 금지 문구를 붙이지 않는다.

한 번의 성공에 맞춘 표현 대신 다른 입력·도메인에서도 지킬 불변식을 남긴다. 효과가 없는 일반론과 중복은 제거하고, 기존의 실제 운영 제약·권한·예외를 단순히 짧게 만들기 위해 삭제하지 않는다.
