# 읽기 쉬운 문서 작성

1. **무엇을 읽으러 오는지 정한다.** 혼자 다시 볼 자료라면 나중에 기억해 낼 개념이나 이유를, 공유할 자료라면 처음 접하는 독자가 이해할 맥락을 살핀다. 이미 드러난 독자와 목적은 그대로 사용한다.
2. **첫 문단에서 독자의 질문에 답한다.** 정책 안내라면 누구에게 어떤 조건이 적용되는지, 학습 노트라면 기억할 개념과 짧은 예시를 앞에 둔다. 실행 순서가 핵심일 때는 첫 단계와 완료 기준을 보여준다. 제목을 읽어도 내용을 찾기 어려운 긴 문단은 독자의 질문에 따라 나눈다.
3. **내용에 맞게 표현한다.** 순서를 따라야 할 때는 번호 목록, 같은 기준으로 선택지를 비교할 때는 표, 분기나 합류를 글로 따라가기 어려울 때는 도식을 쓴다. 짧은 문단으로 충분하면 그대로 둔다. 원자료의 사실·조건·예외를 보존하고 제안이나 미정 사항을 구별한다. 근거는 독자가 해당 설명을 확인하기 쉬운 곳에 둔다.
4. **독자 입장에서 한 번 읽는다.** 핵심을 찾고 예외를 이해하거나 다음 행동을 결정할 수 있는지 확인한다. 낯선 용어는 필요한 곳에서 풀고, 같은 설명을 반복하는 요약·표·장식은 줄인다.

## HTML 요청 시

기본 틀에는 제목과 본문만 둔다. 첫 문단이 요약 역할을 하면 충분하다. 내용이 길어 필요한 경우에만 목차나 접기를 추가한다. 기존 브랜드와 글꼴을 따르고, 색으로 구분한 내용은 글로도 식별할 수 있게 한다.

파일 하나로 오프라인에서 읽도록 필요한 자산을 포함한다. 외부 공유 시 공개 범위는 표시 내용뿐 아니라 내장 자산과 링크에도 적용한다. 데스크톱·모바일에서 글줄 길이와 줄바꿈, 여백, 넘침을 확인하고 링크·접기 등 실제로 넣은 조작을 검증한다. 부분 수정은 영향받는 곳을 확인한다.
