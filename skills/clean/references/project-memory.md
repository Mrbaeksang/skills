# 프로젝트 기억

작업이 끝나도 그 프로젝트에서 계속 유효한 규칙·결정·함정을 프로젝트 저장소의 문서 하나에 둔다. [작업 기록](agent-records.md)은 진행 중인 일을 이어 가기 위한 것이고, 프로젝트 기억은 다음 작업들이 처음부터 알아야 할 것이다. 여러 에이전트·세션·기기가 같은 내용을 보도록 개인 설정이나 대화가 아니라 저장소에 둔다.

## 위치

- 프로젝트 지침(`AGENTS.md`, `CLAUDE.md` 등)이 위치를 정했으면 그것을 따른다.
- 정하지 않았으면 `docs/agent/project-memory.md`를 쓴다. 다른 위치를 찾느라 저장소 전체를 탐색하지 않는다.

## 읽기

- 작업을 시작할 때 파일이 있으면 읽는다. 이 파일 하나만 읽는다.
- 현재 파일·코드·사용자 지시와 다르면 현재 상태가 우선이다. 다른 점은 작업 끝에 기억을 고친다.

## 쓰기

아래 중 하나일 때만 한 줄을 추가하거나 기존 줄을 고친다.

- 같은 지적·수정 요청이 두 번 나왔다.
- 사용자가 이후에도 적용할 결정이나 위임을 했다. 적용 범위를 함께 적고, 해석이면 해석이라고 표시한다.
- 시간을 크게 잃게 한 함정을 찾았다.
- 변경이 사용자에게 닿는 경로를 확인했다.

진행 상황·완료 보고·일회성 사실·비밀값·개인정보는 쓰지 않는다. 코드나 기존 문서에서 바로 알 수 있는 것도 쓰지 않는다. 같은 뜻의 줄이 있으면 새 줄 대신 고친다.

어느 프로젝트에나 맞는 교훈이면 이 파일 대신 일반 관점의 후보로 사용자에게 보고한다.

저장소 파일을 만들거나 고치는 것은 현재 작업의 권한 안에서만 한다. 쓰기 권한이 없거나 분석만 요청받았으면 추가할 줄을 채팅으로 제안한다. 처음 만들 때 프로젝트 지침에서 이 파일을 링크할 수 있으면 링크해 스킬 없이도 읽히게 한다.

## 형식

```markdown
# 프로젝트 기억

## 제품 규칙
- (YYYY-MM-DD) 규칙 한 줄 — 근거: 사용자 요청/이슈 링크

## 결정과 위임
- (YYYY-MM-DD) "사용자의 표현" — 적용 범위: … (해석이면 표시)

## 겪은 함정
- (YYYY-MM-DD) 함정과 피하는 방법 한 줄

## 사용자에게 닿는 경로
- 웹/서버/앱/데이터별 단계와 시점
```

150줄을 넘으면 오래되거나 코드에 반영된 줄부터 정리한다.
