# 테스트 유지 가치

테스트 품질 진단 또는 추가·수정·제거되는 테스트를 검토할 때 읽는다. 평범한 테스트 실행에 전체 suite 감사를 추가하지 않는다.

1. 테스트가 잡는 실제 회귀와 보호하는 공개 계약·불변식을 찾는다. test와 제품 소유 코드, 소비자, 겹치는 테스트를 읽고 필요한 경우 추가된 이력을 확인한다.
2. assertion 없는 실행, 구현을 복제한 기대값, 중복 사례, test-only export, 소스 문자열 검사는 조사 신호다. 포맷·패키징 자체가 공개 계약이면 정적 검사도 유효하므로 형식만으로 제거하지 않는다.
3. 후보별로 `보호 계약 / 실제 실패 조건 / 겹치는 증거 / 변경 후 보호 경계`를 남기고 유지·재작성·통합·제거 제안 중 하나를 선택한다. 독립적인 보호를 입증하거나 대체할 수 없으면 유지한다.
4. 분석·리뷰-only에서는 제안으로 끝낸다. 수정 권한이 있으면 작은 범위에서 변경하고 보존할 회귀를 실행한다. 제품 실패를 감추려고 유효한 assertion을 삭제하거나 기대값을 현재 버그에 맞추지 않는다.

정책 값(가격·한도·보상량)이 바뀌어 많은 테스트가 한꺼번에 깨지면, 그 테스트가 보호하는 것이 값인지 불변식(한 번만 차감, 환불은 받은 금액 그대로, 초과 차감 없음)인지 먼저 나눈다. 불변식 테스트는 값과 분리해 어떤 값에서도 같은 성질을 보게 하고, 정책 값은 그 값을 고정하는 테스트 한 곳에서 확인한다. 깨진 숫자를 하나씩 새 값으로 바꾸거나 불변식 검사를 지우지 않는다.

줄 수·테스트 수 감소가 목표가 아니다. 제거 이유와 남는 보호 계약을 짧게 보고한다.
