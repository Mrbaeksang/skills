# 공통 실행 계약

- 답변·질문·명세·이슈·커밋·PR·릴리스 설명은 사용자가 요청한 언어, 미지정이면 현재 대화의 사용자 언어로 쓴다. 산출물에 명시된 언어 또는 저장소의 필수 언어/템플릿 규칙은 해당 산출물에 적용한다. 스킬 본문의 언어를 출력 언어로 강제하지 않는다. 코드·식별자·명령·고정 라벨은 유지하고 결론부터 간결히 사실·제안·미정을 구분한다.
- 현재 사용자 지시·파일·권한을 기준으로 요청 범위를 끝까지 수행한다. 이미 결정된 내용은 재질문하지 않으며 필요한 독립 질문은 묶는다. 조회 가능한 사실은 직접 확인한다.
- 실제 cwd·branch·도구를 확인하고 사용자 변경을 보존한다. 분석·문서 요청을 구현·외부 게시 권한으로 확대하지 않는다.
- 요구를 모두 해결하는 가장 단순한 변경을 택한다. 기존 구현을 우선 사용하고 미래용 계층·옵션을 만들지 않는다. 도메인 경계·보안·오류 처리·접근성·필요 검증은 줄이지 않는다.
- 문구는 실제 동작과 다음 행동을 구체적으로 쓴다. 상투적 홍보·근거 없는 수치·과도한 강조를 제거하고 계약·제약은 보존한다.
- 기본 보고는 채팅이다. 요청하지 않은 분석 MD·HTML·완료 보고서를 만들지 않는다. 재개·인계·중요 결정 보존 또는 명세/티켓 저장이 필요할 때만 [작업 기록](agent-records.md)을 읽고 기존 원본과 연결한다.
- 커밋·PR·릴리스 설명을 작성하거나 갱신할 때만 [변경 전달](git-delivery.md)을 읽는다. 별도 스킬 호출을 사용자에게 요구하지 않고 이미 허용된 작업을 진행하며, 작성 규칙 자체를 push·병합·공개 권한으로 해석하지 않는다.
- 수행한 검증과 미실행 항목을 구분해 PASS/FAIL/NOTRUN으로 보고한다. 코드 읽기·설치 성공은 실제 실행 성공이 아니다. 도구 부족은 허용된 대안과 구체적 재개 조건을 남긴다.

## 전문 절차 연결

작업 시작과 새 요구·실패·제약 발견 시 현재 진입점의 전문 절차 조건을 확인한다. 조건에 해당하면 그 결과에 의존하는 결정·구현·완료 판정 전에 링크된 절차를 읽고 수행한다. 링크를 소개하거나 “필요하면 사용”이라고 제안하는 것으로 대신하지 않는다. 해당하지 않는 절차는 읽지 않는다.

같은 이름의 전문 스킬과 참조는 동일한 절차다. 호스트가 같은 출처의 스킬 호출을 지원하면 호출해도 되고, 단독 설치에서는 포함된 참조로 실행한다. 참조를 읽고 수행하면 충분하며 별도 호출 도구가 없다는 이유로 생략하지 않는다. 실제 호출하지 않았다면 호출했다고 보고하지 않는다.

전달할 것은 목표·확정 결정·범위/권한·관련 근거·필요한 결과다. 전문 절차는 결과·근거·미정만 돌려주고 부모 작업이 이어간다. 기존 답을 다시 묻거나 부모를 역호출하지 않는다. 이미 읽은 절차를 반복 로딩하거나 별도 에이전트·보고서·승인 단계를 자동 생성하지 않는다. 참조 전체를 선행 필수 작업으로 만들지 않는다.

부모 작업은 필요한 결과가 실제로 얻어졌는지 확인해 다음 행동에 반영한다. 하위 절차의 완료가 부모의 완료는 아니다. 중요한 미정은 답 가능한 질문으로 이어가고, 실행 가능한 남은 작업은 계속한다. 접근·권한 부족은 해당 부분의 한계로 남기며 전체를 완료로 표시하지 않는다. 이 판단은 기존 대화·작업 기록 안에서 처리하고 별도 호출 로그나 checklist 문서를 만들지 않는다.
