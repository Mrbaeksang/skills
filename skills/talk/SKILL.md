# Talk

[공통 실행 계약](references/execution-contract.md)을 읽는다. 기본 산출물은 대화 속 목표·결정·열린 질문이며 파일·이슈·코드를 자동 생성하지 않는다.

1. 이미 말한 의도와 제약을 짧게 정리하고 이번 대화에서 정할 범위를 잡는다. 단순 고민에 전체 제품 설계 checklist를 적용하지 않는다.
2. 결정의 선행 관계를 구분해 지금 답할 수 있는 독립 질문을 한 묶음으로 묻는다. 각 질문에 추천과 선택이 달라지는 조건을 붙인다. 다른 미정의 답에 의존하는 질문은 다음 묶음으로 미룬다. 이미 답한 내용은 다시 묻지 않는다.
3. 사실이 필요하면 직접 확인한다. 외부 근거·기술 사실이 결정에 필요할 때만 [research](references/workflows/research.md), 용어·업무 규칙이 충돌할 때만 [domain](references/workflows/domain.md)을 실행한다. 조사 중인 사실에 의존하는 질문만 기다리고 독립 질문은 진행한다. 스킬 분리만으로 별도 에이전트를 띄우지 않는다.
4. 답에 따라 다음 질문을 다시 고른다. 현재 범위의 목표·결정·중요 미정이 명확하면 짧게 정리하고 멈춘다. 숨은 가정을 확정 사실로 쓰지 않으며 무관한 가지를 끝없이 파고들지 않는다.

사용자가 개발 설계·명세·구현까지 요청했다면 기존 결정과 미정을 해당 작업에 전달한다. 그렇지 않으면 shape/spec/ticket/build로 자동 진행하거나 종료 확인을 반복 요청하지 않는다.
