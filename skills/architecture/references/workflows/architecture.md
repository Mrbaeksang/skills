# Architecture

모듈 경계·공통 책임·의존 방향을 새로 정하거나 변경 파급이 불명확할 때 사용한다. 입력은 목표·기존 구조·보존할 계약이다. 단순한 기존 패턴 재사용에는 경로 확인만 수행한다.

1. [재사용 탐색](architecture/integration.md)으로 실제 등록·호출·설정 override와 소비자를 찾는다. 도메인 용어·소유권이 불명확할 때만 [domain](domain.md)을 실행한다.
2. 현재 구조 유지, 기존 계약 확장, 새 경계가 필요한 안을 관련 범위에서 비교한다. DDD modular monolith를 기본으로 보되 기존 시스템과 과제 크기를 존중한다. CQRS·repository layer·microservice를 자동 추가하지 않는다.
3. 순환·타 모듈 내부 접근·중복 정책과 변경 파급을 실제 경로로 확인한다. 우연히 비슷한 도메인 로직을 global utility로 합치지 않는다. 기술 호환 사실이 부족할 때만 [research](research.md)를 사용한다.
4. 선택 근거·대안·공개 계약·소유 데이터·호환/이행 경로·검증 경계를 반환한다. 중요한 결정의 보존이 필요할 때만 [작업 기록](../agent-records.md)을 따라 기존 ADR/issue 또는 허용된 에이전트 기록에 연결한다. 구조 설계 요청만으로 코드 재배치·전면 재작성을 시작하지 않는다.
