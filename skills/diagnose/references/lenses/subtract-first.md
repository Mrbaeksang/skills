# 빼기 먼저

다듬기·개선·추가를 할 때 먼저 없앨 수 있는 것을 찾는다. 고쳐 쓰거나 새로 더하는 것은 그다음이다.

## 신호

- UI·문구·흐름·설정 옵션·절차·코드 분기를 다듬거나 새로 만든다.
- 사용자가 "군더더기", "너무 친절", "단계가 많다", "복잡하다"고 말한다.

## 확인할 질문

1. 이미 다른 곳에서 전달되는 정보를 반복하는가: 위쪽 제목·탭 이름·버튼 이름·운영체제나 스토어 화면·상태 변화 자체.
2. 사용자의 목표까지 몇 번의 조작이 필요한가. 다음 화면이 버튼 하나뿐이거나 기본값으로 정할 수 있는 선택이 있는가.
3. 확인 단계가 정말 필요한가. 되돌릴 수 없는 삭제·과금·탈퇴·외부 공개처럼 결과가 큰 경우에만 둔다.
4. 이 문장·옵션·분기가 사라지면 누가 어떤 판단을 못 하게 되는가. 답이 없으면 뺀다.
5. 같은 일을 하는 길이 둘 이상인가. 하나로 모은다.

## 수행

- 먼저 뺀 결과를 만들고, 그래도 부족한 것만 더하거나 고쳐 쓴다.
- 법적 고지·동의·되돌릴 수 없는 결과의 경고·실패와 환불 같은 사실 안내는 유지하되 군더더기 문장만 덜어 낸다.
- 일반적인 행동은 그 플랫폼 사용자가 익숙한 형태를 따른다. 모바일 앱에서 뒤로·복사·공유·새로고침·닫기·삭제는 접근성 이름을 단 아이콘이 일반적이다.

## 보고

- 뺀 것, 남긴 것과 남긴 이유를 짧게 나눈다.

## 예

- UI: "복사했어요" 문장 → 아이콘이 잠깐 체크로 바뀌는 것으로 충분하다.
- 코드: 한 곳에서만 쓰는 설정 옵션과 그 분기를 없앤다.
- 절차: 선택 → 미리보기 → 확인 → 실행을 한 번의 조작으로 줄인다.
