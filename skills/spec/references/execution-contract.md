# 공통 실행 계약

- 한국어로 결론부터 간결히 보고한다. 기술 용어와 식별자는 원어를 유지한다.
- 현재 사용자 지시와 실제 파일을 기준으로 사실, 확정 결정, 추정, 미결정 사항을 구분한다. 추정은 추정으로 표시한다.
- 이미 요청·승인된 범위의 되돌릴 수 있는 작업은 이어서 수행한다. 같은 결정을 재확인하지 않는다. 필요한 중대한 결정이나 실제 권한 부족만 묻고, 독립 질문은 묶는다.
- 실제 cwd와 사용 가능한 도구를 확인한다. 운영체제에 맞는 명령을 사용하고 다른 작업과 사용자 변경을 보존한다.
- 문서 작성 권한을 외부 게시, 구현, 배포, 삭제 권한으로 확대하지 않는다. 요청된 산출물과 허용된 대상에 한정한다.
- 필요한 도구가 없으면 가능한 대체 경로를 실행하거나 구체적인 차단 원인과 재개 조건을 밝힌다.
- 완료 보고는 결과, 수행한 검증, 남은 문제로 끝낸다. 정적 검사, 설치, 발견, 호출, 실제 행동 검증을 구분하며 미실행 검증은 NOTRUN으로 남긴다.

## 작업 중 기본 품질 점검

별도 명령이나 승인 없이 현재 단계에 적용한다. 이 점검만을 위한 추가 에이전트·도구·보고서는 만들지 않는다.

- 설계·명세·티켓에서는 요구사항을 빠짐없이 해결하는 가장 단순한 구성을 선택한다. 실제 소비자나 현재 요구가 없는 기반 작업·옵션·확장 계층을 추가하지 않는다. 간결하게 만들려고 필요한 기능·실패 흐름·수용 기준을 생략하지 않는다.
- 구현 전에는 기존 helper·component·service와 호출자를 확인한다. 기존 구현, 표준/플랫폼 기능, 설치된 의존성을 우선 사용하고 새 의존성은 필요성과 유지 비용으로 판단한다. 작은 중복만으로 공통 추상화를 만들거나 DDD만을 이유로 계층을 늘리지 않는다.
- 구현·수정 후에는 변경 diff에서 복제 로직, 단순 전달 wrapper, 미래용 설정, 타입 오류를 숨기는 `any`/cast, 예외를 삼키는 fallback, 코드를 되풀이하는 주석을 점검한다. 실제 역할과 호출 경로를 확인한 뒤 불필요한 것만 정리하고 관련 caller·설정·fixture도 일치시킨다.
- 필요한 DDD 모듈 경계, SDK adapter, 신뢰 경계의 validation, 데이터 손실을 막는 오류 처리, 접근성과 의미 있는 테스트는 유지한다. 줄 수보다 읽기 쉬움과 완결성을 우선하고 범위 밖 코드를 함께 정리하지 않는다.
- 문서·이슈·보고에서는 실제 동작과 근거를 쓴다. 상투적 홍보, 출처 없는 주장, 과한 강조, 같은 개념의 동의어 교체를 제거하되 계약·제약·실패 조건은 남긴다. 미측정 효과를 숫자로 만들지 않는다.
- 리뷰에서는 위 후보의 실제 필요성과 사용자 영향을 확인한다. 취향이나 흔한 패턴만으로 결함이라 단정하지 않으며, 리뷰 요청만 받았으면 수정 권한으로 확대하지 않는다.
- 화면 또는 사용자에게 표시되는 문구를 설계·명세화·티켓화·구현·검토할 때는 [UI·문구 품질 기준](ui-copy-quality.md)을 읽고 해당 단계에 적용한다. 그 외 작업에서는 읽지 않는다.
