# 관찰 기반 추가 검증

실행 결과에 설명되지 않는 동작 또는 추가 실패 위험이 드러날 때 읽는다. 기존 수용 기준과 이미 확보한 증거를 재사용한다.

1. 현재 관찰과 미확인 가설을 구분하고, 가설을 가르는 최소 입력·조작 및 예상 결과를 정한다. 정상 경로에서도 exit/응답뿐 아니라 관련 파일·저장 상태·업무 효과를 확인한다.
2. 독립 검사는 묶어도 되지만 이전 결과에 의존하는 실험은 결과를 읽은 뒤 실행한다. 각 실험에 초기 조건, 실제 입력, 예상/실제 결과, 다음 가설의 이유를 연결한다. 작은 작업은 채팅 또는 기존 증거 형식으로 충분하다.
3. 실패는 허용된 격리 환경에서 같은 초기 상태·입력으로 재현하고 원인을 좁힌다. 실데이터를 임의 초기화하거나 다른 입력의 실패를 동일 재현으로 취급하지 않는다. 재현 불가하면 관찰된 현상과 한계를 구분한다.
4. 수정 권한이 있으면 부모 구현 절차로 결함을 전달한다. 수정 후 원래 실패 입력과 인접 정상 흐름을 최종 변경에서 재실행한다. 테스트 통과만으로 원래 실행 검증을 대체하지 않는다. 리뷰-only에서는 수정하지 않는다.
5. 계약을 확인했거나 안전한 다음 실험이 없으면 멈춘다. 실행 시간·시도 한도는 작업 위험과 실제 도구에 맞춰 정하며 동일 실패를 무한 반복하지 않는다. 탐색 한도에 도달해도 필수 수용 기준의 미실행은 남는다. timeout에서는 부분 결과를 보존하고 자신이 시작한 작업만 정리한다.
