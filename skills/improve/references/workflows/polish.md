# Polish

UI·사용자 문구의 완성도를 개선한다. 입력은 대상 화면/문구, 사용자의 과제, 요청 범위와 보존할 동작이다. 부분 정리와 사용자가 요청한 구조·시각 재설계를 구분한다. 전면 개편을 명시했거나 같은 불만이 반복되어 기존 구조가 과제에 맞지 않는 신호가 있으면 [디자인 방향](design.md)에서 정보 관계·읽기 순서·시각 방향을 재평가한 뒤 돌아온다. 이를 최소 CSS 수정으로 축소하지 않으며, 새 업무 정책·기능·권한으로 범위를 넓히지도 않는다.

1. 실제 콘텐츠, 사용자 과제, 기존 component·token·용어를 확인한다. [UI·문구 기준](polish/ui-copy.md)으로 정보 위계·불필요한 장식·추상적인 카피·동작과 다른 안내를 점검한다. 시각적 설계/수정이면 연결된 시각 품질 기준에서 해당 전문 절차를 읽고 표현 선택까지 수행한다. 취향과 관찰 가능한 사용성 문제를 구분한다.
   CSS·웹 상호작용의 구현 방식을 바꾸기 전에는 [웹 플랫폼 근거](web-platform.md)로 해당 패턴과 지원 조건만 확인한다. 문구만 다듬는 작업에는 조회를 붙이지 않는다.
2. AS-IS 문제와 정한 디자인 목표를 충족하는 가장 작은 변경을 한다. 새 장식·배지·강조의 이유를 제품 맥락으로 설명할 수 있어야 한다. 명시된 브랜드 원칙과 실제 동작을 보존하되, 현재 구현의 색·배치를 승인된 원칙으로 추정하지 않는다. 색·글꼴·카드 자체를 금지하거나 근거 없는 수치·후기·로고를 만들지 않는다. 같은 행동의 이름·오류 후 복구 안내를 실제 동작에 맞춘다.
3. 구현된 화면을 바꿨으면 [verify](verify.md)로 관련 화면 크기·상태·조작·focus 회귀를 확인한다. 시각 변경은 가능한 경우 동일 조건의 이전 화면과 비교하되, 문구 초안만 다루면 의미·사실·용어 일관성을 직접 확인하고 브라우저 검증을 발명하지 않는다.

짧게 수정 결과와 미확인 사실을 보고한다. 성능 개선을 주장하려면 별도 측정이 필요하며 이 절차를 성능 검증으로 대신하지 않는다.
