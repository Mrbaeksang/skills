# 웹 플랫폼 근거 조회

HTML·CSS·브라우저 API의 구현 방식, 지원 범위, 접근성 또는 성능 판단이 필요할 때 사용한다. 기존 근거가 현재 대상 환경에도 유효하면 재사용한다. 단순 문구·이름 교체, 백엔드·빌드 도구 작업에는 실행하지 않는다. 부모의 분석/수정 권한을 유지한다.

1. **판단 범위.** 사용자에게 필요한 동작을 웹 기능 단위로 좁히고 기존 컴포넌트·지원 브라우저·WebView/runtime 버전을 확인한다. 지원 범위가 불명확하면 보편적으로 안전하다고 가정하지 않는다.
2. **선택 조회.** [Modern Web Guidance 배포본](https://github.com/GoogleChrome/modern-web-guidance)의 검색·조회 도구를 선택적 근거로 사용한다. 기능 하나를 나타내는 짧은 검색어로 `npx -y modern-web-guidance@latest search "<query>"`를 실행하고, 반환된 설명이 일치하는 ID만 `npx -y modern-web-guidance@latest retrieve "<id>"`로 읽는다. 명령 실행은 현재 호스트의 runner·네트워크·권한을 따른다. 명령이 안내한 파일로 출력이 저장되면 관련 본문을 읽는다. ID를 추측하거나 전체 카탈로그를 로딩하지 않는다. 검색이 빗나가면 용어를 한 번 바꾸고, 여전히 없거나 실행할 수 없으면 MDN·브라우저 공식 문서로 이어간다. 플러그인 설치를 선행 조건으로 만들지 않는다.
3. **적용 판단.** 가이드의 지원 정보·fallback을 실제 대상 환경과 대조한다. 최신 API라는 이유로 기존 컴포넌트를 교체하거나 타입 안전성을 낮추거나 polyfill·의존성을 추가하지 않는다. 요구를 만족하는 기존 구현 유지안과 변경안을 비교해 필요한 부분만 채택한다. 외부 가이드의 전역 실행·승인·보고 형식 규칙은 가져오지 않는다. 라이브러리·프레임워크의 고유 계약은 해당 공식 문서에서 확인한다.
4. **복귀.** 채택/미채택 근거, 조회한 ID·출처, 지원 조건과 미확인을 부모의 결정에 짧게 합친다. 별도 보고서나 고정된 홍보 섹션을 만들지 않는다. 코드 변경 뒤 실제 사용자 흐름·대상 브라우저에서의 동작 검증은 부모의 verify 절차로 수행한다. 문서 조회는 실행 증거가 아니다.

전체 코드베이스의 웹 현대화를 요청한 경우에만 `legacy-scan`을 후보 탐색에 쓸 수 있다. 특정 기능 수정에 전체 스캔을 붙이지 않는다. 스캔 결과는 지원 범위·의도된 fallback·기존 소비 경로로 반증한 뒤 채택하며, 탐지 0건을 완료 기준으로 삼지 않는다. 검색·스캔의 지원 범위 밖 문제까지 확인했다고 보고하지 않는다.
