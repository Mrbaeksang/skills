# 레퍼런스 분해와 차용

비교 기준이나 참고로 정한 서비스의 화면·효과·동작을 우리 제품에 옮길 때 적용한다. 스크린샷을 보고 인상을 흉내 내지 않는다. 실제 페이지를 분해해 측정한 값과 동작 계약을 가져온다. 사용자가 레퍼런스를 지정했거나 UI 품질 기준에서 비교 기준을 정했을 때 쓴다.

호스트가 제공하는 브라우저 자동화·개발자 도구(DOM, computed style, 네트워크, 성능 기록)를 사용한다. 그런 도구가 없으면 받을 수 있는 HTML·CSS·JS 원문을 읽는다. 그것도 안 되면 스크린샷만으로 관찰한 범위를 구분해 남기고, 측정하지 못한 값을 추정해 채우지 않는다.

## 1. 관찰 대상 고정

URL, 화면 상태(첫 진입, 스크롤 위치, 선택, 로딩·스트리밍 중), viewport, 로그인 여부를 정한다. 같은 조건에서 우리 화면과 비교할 수 있도록 기록한다.

## 2. 시각 값 추출

- **구조:** DOM 계층에서 주요 화면의 구획, 반복 컴포넌트, 층(모달·시트·탭·접기) 수를 확인한다.
- **서체:** 선언된 `font-family`가 아니라 실제로 렌더된 서체를 확인한다. 크기·굵기·줄간격·자간 단계를 표로 만든다.
- **색:** CSS 변수와 실제 계산값에서 배경·본문·보조 텍스트·포인트·상태 색의 역할을 정리한다.
- **간격과 형태:** 간격 단계, 최대 폭과 여백, 반경, 그림자, 구분선을 정리한다.
- **반응형:** 미디어 쿼리 breakpoint와 그때 바뀌는 배치를 확인한다.

값마다 어디서 측정했는지(선택자나 요소)를 남긴다.

## 3. 효과와 모션

- transition·animation의 대상 속성, 시간, easing, keyframes를 확인한다.
- 스크롤 연동 효과와 입력에 반응하는 효과는 발동 조건까지 확인한다.
- 번들과 런타임에서 사용 중인 애니메이션·렌더링 라이브러리를 확인한다.

정지 화면 한 장으로 판단하지 않는다. 시간에 따른 변화를 기록하거나 프레임을 나눠 보고 관찰한다.

## 4. 동작과 프로토콜

- 화면 동작이 서버와 주고받는 내용에 달려 있으면 네트워크 요청 순서, 메서드, payload 모양, 응답 시간을 기록한다.
- 스트리밍 응답은 다음을 확인한다.
  - 전송 방식: SSE, chunked, WebSocket
  - 이벤트 이름과 delta 스키마
  - 조각 크기와 간격
  - heartbeat, 종료·오류 이벤트, 재연결·이어받기 방식
  - 첫 조각까지 걸리는 시간
- 이 관찰을 우리 구현의 계약 근거로 쓴다. 관찰한 사실과 우리가 새로 정한 동작을 구분해 적는다.

## 5. 우리 제품으로 옮기기

측정값을 우리 토큰·컴포넌트 체계로 대응시켜 재구현한다. 우리 사용자 과제에 맞지 않거나 UI 품질 기준의 층 제한에 어긋나는 부분은 가져오지 않는다. 그 판단과 이유를 짧게 남긴다.

## 6. 경계

- 공개된 범위, 또는 사용자 본인 계정으로 정상 접근해서 보이는 범위만 관찰한다. 인증·요청 제한·접근 통제를 우회하지 않는다.
- 측정값·구조·동작 원리는 가져온다. 로고·이미지·유료 폰트 파일·고유 문구·소스 코드 원문은 복사하지 않고 재구현하거나 라이선스가 맞는 대체물을 쓴다. 대체했다면 무엇을 무엇으로 바꿨는지 기록한다.

## 7. 검증

같은 viewport·상태에서 레퍼런스와 우리 화면을 나란히 캡처해 비교한다. 모션은 같은 조작의 시간축으로 비교한다. 스트리밍은 같은 형식의 응답을 우리 구현에 재생해서 표시 결과를 확인한다. 차이가 남은 항목은 의도한 차이인지 결함인지 구분해 보고한다.
