# 상태·비동기·복구 검증

저장 상태 변경, 작업 큐, 재시도, 중복 또는 동시성이 관련될 때 읽는다. 제품의 명시된 보장에 해당하는 행만 선택한다.

| 계약 | 실제 관찰 |
|---|---|
| 정상 처리 | 요청 수락 → enqueue → 처리 → 최종 업무 효과를 구분 |
| 입력·권한 거절 | 기대 오류와 금지된 상태 변경이 없음을 함께 확인 |
| 중복·멱등성 | 같은 요청/event 재전송 후 영속적 효과의 개수와 반환 계약 |
| 동시성·순서 | 통제된 경쟁 연산의 관련 완료 순서와 최종 불변식 |
| 부분 실패·복구 | 효과 발생 전후 실패 주입, 재시작·재시도, 중복과 미완료 상태 |
| timeout·취소 | 남은 작업·부분 데이터·종료와 허용된 복구 경로 |
| 의존 실패 | 재시도 한도·최종 오류·데이터 보존·dead-letter 등 명시된 처리 |

2xx나 job ID는 최종 완료가 아니다. 모든 시스템에 exactly-once를 요구하지 않는다. 반복 실행의 결과는 버그가 있는 이전 출력이 아니라 문서화된 계약과 비교한다.

기존 native 명령·API·테스트 도구와 합성 데이터를 우선 사용한다. 실패 주입·재실행의 영향이 격리됐는지 확인하며, 분석 권한을 운영 데이터 변경 권한으로 확대하지 않는다. 실패 주입을 정상 처리했으면 PASS일 수 있지만 서비스 부재로 검사 자체를 못 했으면 NOTRUN이다. 각 결과에 초기/최종 상태와 실행 근거를 연결한다.
